## 변경

HF 소유 profiling/planning이 고정 모델·runtime·Python 소스·작업 크기에 결속된 실제 stage profile을
소비한다. CPU/CUDA의 공유 용량, reserve, 비활성 장치와 연속 cut을 검사하고 기존 실행용 plan을 만든다.
`prefill_chunk`를 plan에 전달하며 scenario와 실제 `StageSessions` 소비 경계 모두 초과 입력을 거부한다.
기존 llama.cpp 계획기는 유지하고 `npm run test:model-loading`에서 양쪽 시험을 함께 실행한다.
이기종 BF16, 미측정 조합, 원격 서비스나550B의 수용으로 확대하지 않는다.

## 실행 증거

기존 원자료 root는 `layers/adapters/hf/target/loading-planner-20260915/`다. 새 재현은 계획의 root target을 따른다.

최초 workspace 실행은550B 준비 agent가 점유한 `target/debug/p4-agent.exe` 파일 잠금으로
빌드 실패했다. 해당 실패 로그를 보존하고 별도 `--target-dir`로 전체 시험을 끝냈다. ignored7개와
미실행 feature-off 전체 재시험은 성공 수에 포함하지 않는다. 기준 HF 이관의 on/off 증거는 별도다.

실제 profile/verify와 event bundle의 Python 파일 hash가 최종 원본과 일치한다. 이 인수에서는 위
시험을 새로 실행한 것으로 세지 않고 동시 작업의 최종 종료 로그·summary·소스 결속을 직접 확인했다.
550B는 이 CPU 시험들이 끝날 때 아직 LOAD 단계였으므로 추론 비용 측정과 겹치지 않았다.

## Changes

HF-owned profiling/planning consumes real stage profiles bound to the pinned model, runtime, Python source and workload size.
It checks CPU/CUDA shared capacity, reserve, disabled devices and contiguous cuts, and produces a plan for the existing runner.
`prefill_chunk` is passed into the plan, and both the scenario and the real `StageSessions` consumption boundary reject over-limit input.
The existing llama.cpp planner is kept, and `npm run test:model-loading` runs both test suites together.
This is not extended to acceptance of heterogeneous BF16, unmeasured combinations, remote services or 550B.

## Confirmed behavior and boundaries

- Opaque binary, empty frames, consecutive frames and exactly limit-sized frames were round-tripped through a real separate Python process.
- Even with a valid frame appended after invalid magic/version/reserved/oversized length, the peer consumed and output 0 complete frames.
- Header/body truncation returns no payload. Oversized lengths are rejected before the body read call.
- Short reads/writes are handled, and the causes of partial write, flush and read failures are preserved.
  Send input bytes are unchanged, and a failed direction is not reused. Caller-owned streams are never closed on the transport's own initiative.
- The per-role production/test/fixture/tool folders are bound to the [folder rules](../../../docs/structure/README.md).
- `git check-ignore --no-index models/weights.bin python/p4hfadapter/models/example/loading/__init__.py`
  printed only the root weight path. Future model source is not ignored.

## Not done and next work

With no model or GPU selected, REF/Q/MOD, model tensor/identity validation, retained reservation/settlement, worker lifecycle,
the Rust bridge, physical-host distribution and performance/SLO were not run. This is not judged as all of WIRE-01, or S4, being complete.
Blocking stream deadlines, forced termination and thread safety are also outside the scope of this implementation.

The next work is to take the target HF model ID and devices, and investigate and implement that vendor's execution and quantization kernels in dedicated
`configuration/loading/reference/` folders. No common model framework is added.

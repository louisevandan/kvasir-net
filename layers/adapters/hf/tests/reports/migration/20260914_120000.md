## Failures retained and limits

- Collecting diagnostics for the first Cargo failure hit a Windows cp949 decode error, so subprocess UTF-8 was made explicit.
- A matrix given a root-relative path could not find the binary after changing the child cwd. It passed after making input paths absolute, and an independent copy with the fix removed reproduced the same consumption failure.
- The first two full workspace runs failed the HF LOAD 300ms limit because Python fixtures started concurrently. Only LOAD startup was isolated with a mutex. The existing 300ms limit and parallel execution after readiness were kept. An independent removal mutation fails, and the final default parallel suite passed. The earlier failure logs are also preserved.
- Offline uv sync failed because the certifi cache was missing. A new venv was created with the same Python, and the existing installed site-packages were copied. This is not described as a completed wheel reinstall. Actual imports and the 35 lock versions were verified.
- Adding a local firewall rule was rejected for insufficient privileges, so an SSH reverse tunnel was used for the return route between the two hosts. This is not evidence for direct LAN acceptance, TPS/performance, or H0–H7/SLO acceptance. It also does not claim that the existing BF16 heterogeneous failure is resolved.
- Moving the empty original folder failed because a process held it, and deletion was blocked by the auto-approval review policy. All source, Git and untracked assets were moved and preserved, but the empty `F:/dev/p4hfadapter/.git` directory and its parent remain. Full deletion of the original directory is incomplete.

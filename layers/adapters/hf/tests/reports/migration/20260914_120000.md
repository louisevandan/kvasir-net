## Failures retained and limits

- 첫 Cargo 실패 진단 수집에서 Windows cp949 decode 오류가 발생해 subprocess UTF-8을 명시했다.
- root 상대 경로를 받은 matrix가 child cwd를 바꾸면서 binary를 찾지 못했다. 입력 경로 절대화 후 통과했고 독립 수정 제거본에서 같은 소비 실패를 재현했다.
- 초기 전체 workspace 2회는 Python fixture 동시 시작 때문에 HF LOAD 300ms 제한에서 실패했다. LOAD startup만 mutex로 격리했다. 기존 300ms 제한과 준비 후 병렬 실행은 유지했다. 독립 제거 변이에서 실패하고 최종 기본 병렬 suite는 통과했다. 이전 실패 로그도 보존했다.
- offline uv sync는 certifi cache 부재로 실패했다. 같은 Python으로 새 venv를 만든 뒤 기존 installed site-packages를 복사했다. wheel 재설치 완료로 표현하지 않는다. 실제 import와 lock 35개 버전을 검증했다.
- 로컬 방화벽 추가가 권한 부족으로 거절돼 두 host의 반환 경로에 SSH reverse tunnel을 사용했다. 직접 LAN 수용·TPS/성능·H0–H7/SLO 수용 증거가 아니다. 기존 BF16 heterogeneous 실패도 해소했다고 주장하지 않는다.
- 빈 원본 폴더의 이동은 프로세스 점유로 실패했고 삭제는 자동 승인 검토 정책에 차단됐다. 소스·Git·비추적 자산은 모두 보존 이동했지만 `F:/dev/p4hfadapter/.git` 빈 디렉터리와 부모만 남았다. 원본 디렉터리 완전 삭제는 미완이다.

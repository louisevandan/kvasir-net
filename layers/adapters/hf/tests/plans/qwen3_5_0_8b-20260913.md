# Qwen3.5-0.8B-specific partition script verification

Goal: partially load the pinned real model according to the node plan, and compare prefill and decode against the official full model.
Environment: Windows/CPython 3.13.15, torch 2.14.0+cu130, transformers 5.17.0, local RTX 4080+3090 and CPU.
Model/configuration, limits and verdicts follow the pinned contract in the [model document](../../docs/models/qwen3_5_0_8b/README.md).

| Stage | Run and expected result |
| --- | --- |
| Weight acquisition | preparation command; bind the SHA256 of the pinned-revision files into the manifest |
| Invalid plan | dependency-free suite and inspect consumption; reject gap/overlap/model/revision/quantization/limit |
| Single GPU | compare logits and tokens against the official full model; EOS and re-acceptance of the next request |
| Various cuts | at 12/12, 5/14/5 and 3/1/20, real separate processes each hold only their own weights/state |
| Devices | record GPU, CPU+GPU and CPU-only as separate precision arms |
| Scenarios | short, 32-token chunked prefill, interleaved multiple requests, cancellation at a step boundary while the remaining requests continue |
| Rejection | model-runtime state checks; 0 computation and 0 state creation for invalid dtype/shape/position/issue/vision token |
| Mutation | in an independent copy, remove plan coverage, the tokenizer return contract, the duplicate-issue check and the cache local-index conversion |

The full matrix is `scripts/verification/qwen3_5_0_8b/run.py`, state rejection is `scripts/verification/qwen_state/run.py`,
and independent mutation is `scripts/verification/qwen_mutation/run.py`. Each command runs with the model environment's Python.
The default `scripts/testing/run.py` owns the tests that need only the standard library and does not replace the runtime tests.

Logits verdict: atol 0.125, rtol 0.01, identical greedy tokens. The tolerances were fixed before the first model run.
The failure of the BF16 heterogeneous arm is preserved as is, and FP32 is judged as a separate input/precision arm.
On a worker execution failure, the first error, cleanup errors, the outputs of completed requests and the stage trace are preserved.
An admission failure does not start the worker. Recovering the partially generated output of in-progress requests is outside this runner's guarantees.

Not done: P4 retained consumption/ledger, real multiple physical hosts, multimodal/MTP, quantization/compression kernels,
physical batching, SLO/throughput acceptance. Element-wise comparison of real cache tensors is a separate follow-up; this comparison covers
repeated logits and per-stage observations of cache ownership, position and release.

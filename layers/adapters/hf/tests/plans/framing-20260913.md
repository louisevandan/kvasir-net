# 로컬 IPC framing 검증

목적: 모델 의미를 해석하지 않는 blocking binary stream framing을 실제 별도 Python 프로세스에서 검증합니다.
현재 모델 미선정이므로 S4a의 독립 전송 부분만 앞당깁니다. 모델 worker·Rust bridge 검증은 아닙니다.

- 환경: Windows, 설치된 Python 3.13.15, 표준 라이브러리만 사용. 모델/GPU/P4 수정 없음.
- 실행: 저장소 루트에서 `python -B scripts/testing/run.py`.
- fixture: `tests/fixtures/framing_peer/main.py`; 입력을 production receiver로 소비하고 production sender로 반환.
- 정상: opaque binary·빈 payload·연속 frame·상한 경계·짧은 read/write·clean EOF.
- 거절: magic/version/reserved/size 오염은 payload 소비·출력 0. 과대 길이는 body read 전에 거부.
- 장애: 모든 header/body 절단, read/write/flush 오류, 쓰기 진행 없음. 최초 원인 보존과 stream 재사용 금지.
- 소유권: invalid send는 write 0과 재사용 가능, partial send는 원본 bytes 보존·재시도 금지.
  stream close와 상위 정산은 호출자 책임이며 전송 성공을 GPU 완료나 요청 해제로 해석하지 않습니다.
- RED: 소스 구현 전에 같은 test runner의 실패를 기록합니다.
- 변이: 독립 복사본에서 version/길이 상한/수신 실패 상태/송신 실패 상태/닫힌 read 오류 분류 수정을
  각각 제거하고 동일 suite의 실패를 확인합니다. `python -B scripts/verification/framing_mutation/run.py`로 재현합니다.
  복사본 source/test SHA256, child decoder 경로·hash, Python identity, exit code와 전체 로그를 보존합니다.
- 산출물: `artifacts/framing/<run-id>/` 원본 로그/소스 digest, `tests/reports/framing/` 요약.
- 미검증: nonblocking/deadline/강제 종료·thread safety·tensor/identity schema·예약 원장·GPU 상태 반환·P4 통합.

Observed 2026-08-18 KST with the built CUDA staged server and
`S:\models\Qwen2.5-1.5B-Instruct-Q8_0.gguf`. No file below
`apps/p4/layers/adapters/llamacpp/upstream` was changed.

The tail runtime now exposes the patched llama.cpp `terminal_*` tensors as
ordinary HOP result descriptors. The full and two-stage runs returned the same
descriptor set:

```text
result_output: F32 [151936], 607744 bytes
result_norm:   F32 [1536],   6144 bytes
```

With the default `AUTO` attention policy, the numeric equality test initially
did not pass:

```text
staged logits differ: values=153472 max_abs=1.1567078 max_relative=1.9993175
```

The diagnostic showed that the full graph selected Flash Attention while the
partial graph selected a different attention kernel. Pinning both plans to
`--flash-attn 0` makes the comparison apples-to-apples:

```text
LOGITS_EQUAL full_outputs=2 staged_outputs=2 values=153472
max_abs=0.000000000e0 max_relative=0.000000000e0
```

The separate greedy sampled-token test also passes for the full, 2-stage, and
4-stage paths (`21927` for all three). Strict logits validation therefore
requires an explicit common attention policy; AUTO may legitimately select
different kernels for full and partial device assignments.

The test pins the policy in its plan rather than loosening the numerical
tolerance. No upstream source was changed.

The same built server did pass a real two-stage multi-sequence prefill test:

```text
REAL_TWO_STAGE_MULTI_SEQUENCE sequences=2 n_tokens=10 stage1_elapsed=213.4034ms descriptors=2
```

Both sequence identities and both cut-set payloads reached the second stage;
the test also confirmed that prefill returns no sampled outcome.

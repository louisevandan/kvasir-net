PremiseWhat it is · what it is not02 / 16

What matters about this layer's claim is that it is “verifiable”

It is not general-purpose messaging. It knows its workload in detail and is cut to that shape. Everything else is deliberately absent.

What it is

  • A model split across several nodes by layer range
  • A prefill chain source-routed through the nodes
  • A node-driven decode ring where one token takes one lap
  • Cohort batching under a declared ceiling

What it is not

  • A general-purpose messaging system — nothing the workload does not use
  • The owner of throughput — it does not run the model
  • TLS, authentication, authorization — none. Use only inside a trusted network
  • Durable state — a restarted agent has no nodes
Claim: problems in the running system do not belong to this layer. — that this claim is testable is the point of the design. Every stage runs against a mock backend that only does arithmetic (no device, no runtime, nothing underneath to blame), and the agent reports its lane depths side by side with node depth.
Sources docs/overview.md, docs/constraints.md, layers/agent/src/agent(NodeStatus) · when `running` was a bool, it was equally true at 1 and at 100
TopologyThere is one process type03 / 16

There is no controller. The node lives inside the agent

The path an agent takes to reach another agent is the same path it uses to answer the outside world. There is no separate, special entry process.

OUTER

The requesting side. It owns placement, load plans, chains and every business identifier. The agent only reports machine facts and never turns them into placement.

AGENT

A socket program with one main queue and a worker pool. Its only internal entity is the node.

NODE · ADAPTER

A node is just an id until a load attaches an adapter. It holds its own queue and its own long work. The adapter receives hops and reports events.

Sources README.md, docs/overview.md, docs/event-protocol-v2.md · run: `p4-agent 0.0.0.0:52001 tcp://THIS_HOST:52001`
wireThe header alone gives the full length04 / 16

Every hop reads the envelope; only the destination reads the body

This split is the design. A relay forwards by copying bytes it never decoded, so forwarding cost does not depend on the message kind, and a new message kind cannot make relays heavier.

Why the body ceiling was raised to 2 GiB is kept in a code comment. A staged prefill hop carries one hidden-state cut per sequence and token, as F32. A 2,048-wide model with a 5,000-token prompt makes one sequence 39 MiB and a 10-wide prefill window 391 MiB. The old 128 MiB ceiling cut that window at 3 — and with the deployment healthy, 53 of 60 requests failed with `HOP envelope too large`.
Doc/code gap (measured): `docs/api.md` says “P4B1 v6 · body max 1 MiB”, but the code is v8 · 2 GiB. The code comment also owns the reason for the v7→v8 bump: SessionClose changed from a one-way broadcast to an ack contract, and a half-old fleet looks healthy until the first early close, then silently leaks stages on the old side. The version bump turns that into a two-way rejection before a single body byte.

wireevent envelope05 / 16

P4 knows nothing of prompts, tokens or KV

Every event is self-describing so it can be routed without decoding the payload. Only the concrete adapter named by content-type and adapter_kind is entitled to interpret those bytes.

An Endpoint is a value, not a registry key

Agent
{ address }
Node
{ agent_address, node_id }
Outer
{ ingress_agent_address, channel_id, connection_generation }
source cannot double as the reply address. The tail node receives data from the node before it, but the output belongs to the OUTER that started the inference. A stable `channel_id` points at that stream, and `connection_generation` keeps a new stream from flowing into an old socket after a reconnect.
Intermediate agents do not rewrite source, target or return_route. When an adapter finishes work, it creates a new event with itself as source, the exact next endpoint as target, and the causing event as causation_id.

Fields it does not define: prompt · token · max-token · Prefill · Decode · KV · layer · tensor · batch · backend. Ordering and duplicate suppression come from per-source sequence + event identity; inferring logical order by hashing the transport route is not valid.

agent coreVerdicts and lanes06 / 16

A frame is judged exactly twice, and priority is bounded

One route, one worker. Order within a route is the only ordering guarantee, and it comes from registration order. Handing consecutive frames of one route to different workers throws that away, and to the caller it looks as if P4 reordered the stream. Hashing the route keeps each route serial while different routes run concurrently.
Sources layers/agent/src/worker/judge, layers/agent/src/queue/main, docs/architecture.md, docs/constraints.md · forwarding also happens in the dispatcher, not in a task of its own
agent coreThe node's long work07 / 16

A node advances on exactly two events — there is no timer

A node's speed is the backend's speed. A third trigger would be a guess about that speed.

Cancellation and deadlines

Decided at this boundary. There is no way to abort a hop, and no need for one — not starting the next one is the whole mechanism.

A hop carries a window

Batching is the node's decision, capped by the value the load declared and never derived. The window is composed close to the work — a gate further away reported a ceiling that disagreed with arrivals.

Nothing returns a value

A handler is a procedure whose only output is putting frames on a queue. A response path tied to the call stack dies with that frame, so the requester registers a continuation.

Isolation contractThere are three pass conditions09 / 16

“include 0 · compiles · clean on this pin” does not mean isolation is done

A refactor that passes only one of the three is not reported as full layer isolation.

01

Dependency isolation

Upper code cannot know lower implementations by name. The build enforces that only allowed surfaces are depended on.

  • Means: protocol/agent/adapter-contract crates have no normal dependency on a concrete backend. Registration happens in the entrypoint
  • pure scheduler/ledger tests build without a llama checkout, GPU or network
Measured gap: `layers/protocol` has no `[dependencies]` section at all (0 dependencies). But `adapters/adapter` currently depends on p4-protocol·serde·serde_json — the “does not even depend on protocol” in `docs/implementation.md` reflects that earlier point in time.
02

Authority isolation

Transport and policy cannot commit the execution ledger or KV on their own. Layers are not split by file names alone.

  • Criterion: who commits state, and who only executes effects
  • L3 yields a candidate. A rejected issue never silently spends exec quota, credit or turn
  • L1 commits request delta, in-flight ledger, settle receipt, output/release intent in one commit
  • L5 executes committed effects and returns the results. If unclear, it leaves them Uncertain/fenced
No token/native effect goes out ahead of settlement approval. Success at the tail engine is not output authority that bypasses ledger approval.
03

Semantic isolation

Even an upstream change that compiles cannot be promoted if it breaks an existing contract.

  • Means: conformance catches semantic changes, and the product LOAD enforces that verification result and the execution identity
  • Advertising a capability that cannot be honored fails LOAD/conformance
  • An unknown value is never read as “default CUDA” or “supported”. A mixed-version fleet has a defined rejection
A clean replay on the pin is not proof of semantic compatibility. If an opaque class exposes `impl()` and a consumer can include an internal header, the boundary is not finished — confirm by compiling a real consumer.

AdapterBatching layers L0–L510 / 16

Only one layer commits state

OUTER decides the model, topology, SLO, request arrivals and snapshot triggers; the adapter composes eligible rows and batches. No llama-specific batching/KV rules go into the P4 core.

Invariants a strategy must hold (excerpt)

  • Residency precondition: before a row runs on a stage, that stage's prefix KV and auxiliary state must be valid — this does not mean draining the whole pipeline before issuing every row
  • No submission without proof: never assume KV survived a failed execution
  • Snapshot consistency fence: Checkpoint, Persist and Fork only at a stop point with zero in-flight rows and every stage settled — a snapshot exported mid-batch is a wrong answer with an ambiguous position

staged executionStage chain and output authority11 / 16

Where native compute runs and who may approve output are different things

Even if the tail node computes the result, OUTER output is issued only after the head, which owns settlement, verifies and commits the ledger.

What SESSION v4 installs

  • Required: `load_generation`, `session_id`, the full order `stages: [{agent,node,generation}, …]`, the receiving node's `stage_index`
  • role/first/next declarations were removed. Unknown top-level fields and old v3 commands are rejected
  • Checks node addresses, nonzero generations, duplicate-free identities and a valid index, and installs only if the index's full endpoint equals the actual worker and the envelope target
  • Different generations of the same agent/node cannot be declared as different stages at the same time
The envelope source of OUTPUT is the configured first endpoint. OUTER checks the full endpoint, including agent address, node ID and node generation, plus load/session/request, target/return route, correlation and position. The tail is not also accepted just because it is a configured node.
The limits are stated plainly. Per-receiver checks alone do not prove fleet-wide agreement on the same declaration, user/network authentication, or freshness after a process restart. The current stage path supports only 2 or more stages, with head and tail separate — a limit from having no single-stage implementation, not a placement policy to cut nodes per device.

upstreamAbsorbing llama.cpp changes12 / 16

The official checkout stays untouched. One directory per pin owns the patches

If even one patch does not apply cleanly, the build stops before CMake. The official checkout is never edited to get a build through.

Where the patches touch is exactly where isolation happens. ggml-backend·ggml-rpc, public pipeline ABI, llama-context/graph/memory headers, model-loader, KV stage window, stage memory residency(+recurrent), MTP tail stage, speculative sequence lifecycle, stage noalloc memory breakdown — all inside the compat boundary, never surfacing to upper layers.
Upstream adaptation ends inside the allowed modules. Not only direct includes but also transitive includes, linking, forward declarations, public signatures and imported relinks are checked together. Never widen the allowlist and then report “0 violations”.

InvariantsWhat happened without them14 / 16

Most invariants are here because they broke once

InvariantWhat went wrong without it
The socket reader only enqueuesHandlers ran inside the read loop, so every handler's run time piled up there
The node's queue holds the long workOtherwise GPU time shows up as agent queue depth and nothing can be attributed
One route, one workerFrames of one route raced across several workers, and to the caller it looked as if P4 had reordered the stream
The node's select is unbiasedFavoring completions starved arrivals completely — sitting in the channel, in no queue, invisible
The advertised address is one peers can reachBoth agents called themselves `127.0.0.1`, finished prefill and stopped after one token — the lap resolved to whichever machine held the frame
Advertise hints are parsed, not concatenatedAppending the bind port to a hint that already had a port gave `HOST:52001:52001` — it parses, resolves nothing, and reports itself ready
The node run loop ends when its handle is droppedThe node holds its own event sender, so a loop waiting for that channel to close waits on itself. Every replaced or deleted node stayed resident with its adapter, queue and in-flight map
Quiet peers are releasedThe peer map was append-only for every address ever seen — bounded on a fixed fleet, unbounded the moment callers come back on new ports
A declared frame length is capped before allocationThe header is 16 bytes and can claim anything. The ceiling makes that trap cost 1.25MB per connection, not the process
Only the end of the chain produces tokensIf middle stages also count, an n-stage chain emits n tokens per lap
Expired work is answered, not droppedA caller waiting for a terminal that never comes — that is what a leaked route looks like

## Scope of this version

P4 is the communication layer for distributed inference: agents on multiple machines carry the work and a concrete adapter (llama.cpp staged server) executes it.
The v0.9.0 candidate includes the implementation below. Real-hardware runs used **one physical host (RTX 3090 ×2, `m42-server2`)**, and failure preservation was also verified with consumer-path and real-CLI tests.

- Fixed-length wave requests (512 requests, resident 256) **complete, release and clean up all the way to the end** — previously they never ran to completion because the
  response retention budget on the release/settlement control path blocked them.
- A failed run does not lose results it had already accepted.
- The load plan for hybrid (recurrent) models does not actually allocate state during planning.
- A measurement tool that recomputes a run from its artifact files alone, and measured records that change one condition at a time.

## What was verified

**Initial release gate (2026-09-10, 3090×2).** The first passes below do not carry over automatically to new Rust binaries. The last section and the gate document own the latest status. The gate document owns run IDs and hashes.

| `pressure` (2B, 4 stage, resident 256, 512 requests) | 512 / 512 / 512, error null |

| `release_35b_must_refuse` (r256, ctx 1024, ubatch 4096) | The memory plan refuses (`exceeds currently free memory`) |

- Real-hardware comparison against the earlier defect: on 09-09, with the same server and launcher, `pressure` stopped at 512 / 64 / **0**; after changing only the adapter,
  two runs reached 512 / 512 / 512. Slots 0–255 served 2 requests each, and all 512 incarnations were unique.
- The recurrent buffer in the planning pass is **0.00 MiB** at r96 and r256, the `context` expected-size report is kept, and r256 was admitted with `required 19.72 ≤ free 22.76`.
- Workspace `cargo test --workspace --no-fail-fast --locked` **1,374 passed / 0 failed / 7 ignored**, all Node tests **146 / 0** (101 in the existing scope + 45 validator tests),
  docs-lint 91 files clean, compat manifest and patch classification valid (26 patches), private headers 81 clean, CTest 15 / 15.
- The Rust consistency fixes left failing counterexamples, consumer-path tests and mutation testing in a separate worktree.
  This acceptance of 0026 rests on the CUDA Release build and the limited real-hardware gates above; full non-regression verification belongs to the next version.

## What was not verified — scope this release does not claim

- All of verification protocol **H0~H7**. In particular: H1 on the normal corpus, H2 with sustained 8 waves and 8R, overload H3, H6 across multiple physical computers, and sustained operation H7.
- **Multiple physical hosts.** Every real-hardware run used two cards in one host.
- **Service approval.** Every load-test response ends with `length` at 200 tokens per request. The content was read directly to check topic fit, language and non-degeneration,
  and `<think>`/ChatML marker leakage is 0/512, but **this is not a quality approval of complete responses.**
- **TPS improvement.** `pressure` never completed before, so there is no baseline to compare against. 313.80 TPS (35B, burst of 64 requests / 2 s) is **the best single-run value among the tested conditions**,
  neither a hardware limit nor an optimum. The differences from changing the arrival pattern reflect input sensitivity.
- **GPU saturation.** `utilization.gpu` is the fraction of time a kernel is active, not SM occupancy. Attributing the gap between 2B at 21~33 % and 35B at 37~51 %
  to model size is a hypothesis.
- Loading and completing at resident 256 is **not a service approval for raising resident.**

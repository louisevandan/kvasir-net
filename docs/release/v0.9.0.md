# P4 v0.9.0 — 릴리즈 후보 노트 (최종 봉인 보류)

**현재 상태: 코드·로컬 검증·후보 보관 완료, 실기 최종 봉인 BLOCKED.** Windows Update 재시작이 최신 r256 실행을 중단했다.
42mob 로그인 복구 뒤 r256 재판정과 마지막 메모리 부족 거부 게이트가 필요하다. 기존 미공개 tag는 archive ref에 보존한다.

> 이 문서는 **이 버전이 검증한 것의 봉인**이지 [검증 규약 §7](../distributed-batching-verification.md)
> 최종 체크리스트의 달성이 아니다. 아래 "검증하지 않은 것"이 이 릴리즈가 주장하지 않는 범위다.
> 현재 상태와 다음 순서는 [로드맵](../distributed-batching-roadmap.md)이 소유하고, 모든 숫자는 각 증거 문서가
> 인용하는 보존 산출물에서 나온다. 최종 산출물과 tag 결속은 마지막 절에 기록한다.

## 이 버전의 범위

P4는 여러 머신의 에이전트가 일을 나르고 구체 어댑터(llama.cpp staged server)가 실행하는 분산 추론의
통신층이다. v0.9.0 후보는 아래 구현을 포함한다. 실기는 **한 물리 호스트(RTX 3090 ×2, `m42-server2`)**이며, 실패 보존은 소비 경로·실제 CLI 시험으로도 검증했다.

- 고정 길이 웨이브 요청(512건, resident 256)이 **끝까지 완료·해제·정리**되는 것 — 이전에는 해제·정산 제어 경로의
  응답 보관 예산에 막혀 완주한 적이 없었다.
- 실패한 실행이 승인한 결과를 잃지 않는 것.
- 하이브리드(recurrent) 모델의 적재 계획이 계획 중에 상태를 실제 할당하지 않는 것.
- 실행 산출물을 그 파일만으로 재계산하는 측정 도구와, 조건을 하나씩 바꾼 실측 기록.

## 검증된 것

**초기 릴리즈 게이트(2026-09-10, 3090×2).** 아래 최초 통과를 새 Rust 바이너리로 자동 승계하지 않는다. 최신 상태는 마지막 절과 게이트 문서가 소유한다. 실행 ID와 해시는 게이트 문서가 소유한다.

| 게이트 | 결과 |
| --- | --- |
| `smoke` (2B, 4 stage) | 1 / 1 / 1, 오류 null |
| `pressure` (2B, 4 stage, resident 256, 512요청) | 512 / 512 / 512, 오류 null |
| `pressure_35b` (Ornith-1.0-35B, 2 stage, resident 96) | 512 / 512 / 512, 오류 null |
| `release_35b_r256` (35B, 2 stage, resident 256) | 512 / 512 / 512, 오류 null — 09-09에 계획이 거부하던 구성 |
| `release_35b_must_refuse` (r256, ctx 1024, ubatch 4096) | 메모리 계획이 거부(`exceeds currently free memory`) |

- 이전 결함의 실기 대조: 09-09에 같은 서버·launcher로 `pressure`가 512 / 64 / **0**으로 멈췄고, 어댑터만 바꾼
  뒤 두 번 512 / 512 / 512. 슬롯 0–255가 각 2건씩, incarnation 512개 고유.
- 계획 pass의 recurrent 버퍼가 r96·r256에서 **0.00 MiB**, `context` 예상 크기 보고 유지, r256이 `required 19.72 ≤ free 22.76`으로 admitted.
- 워크스페이스 `cargo test --workspace --no-fail-fast --locked` **1,374 passed / 0 failed / 7 ignored**, Node 전체 **146 / 0**(기존 범위 101 + 검증기 45),
  docs-lint 91 files clean, compat manifest·patch 분류 valid(26 patches), private headers 81 clean, CTest 15 / 15.
- Rust 정합성 수정은 실패 반례·소비 경로 시험·분리 worktree의 변이 검증을 남겼다.
  0026의 이번 수용 근거는 CUDA Release 빌드와 위 제한된 실기 게이트이며, 전체 무회귀 검증은 다음 버전이다.

## 검증하지 않은 것 — 이 릴리즈가 주장하지 않는 범위

- 검증 규약 **H0~H7** 전부. 특히 정상 corpus의 H1, sustained 8 wave·8R의 H2, overload H3, 여러 물리 컴퓨터의 H6, 지속 운영 H7.
- **다중 물리 호스트.** 모든 실기는 한 호스트의 카드 두 장이다.
- **서비스 승인.** 모든 부하시험 응답이 요청당 200토큰 `length` 종료다. 내용은 직접 읽어 주제 적합·언어·비퇴화를 확인했고
  `<think>`·ChatML 마커 유출 0/512이지만, **완결된 응답의 품질 승인은 아니다.**
- **TPS 개선.** `pressure`는 이전에 완주한 적이 없어 비교 기준선이 없다. 313.80 TPS(35B, 64건/2초 버스트)는 **시험한 조건 중 단회 최고치**이며
  하드웨어 한계도 최적값도 아니다. 도착 패턴을 바꾼 차이는 입력 민감도다.
- **GPU 포화.** `utilization.gpu`는 kernel 활성 시간 비율이고 SM 점유율이 아니다. 2B 21~33 %, 35B 37~51 %의 차이를
  모델 크기로 귀속하는 것은 가설이다.
- resident 256 적재·완주는 **resident 상향의 서비스 승인이 아니다.**

## 봉인 상태와 실제 보관물

**정식 v0.9.0 봉인은 BLOCKED**이며 릴리즈 후보를 보존했다. 제품 기능·시험 수정은 `3302591fc`이고,
이후 후보 보존 commit은 문서/manifest와 해시 파일 줄바꿈 규칙만 바꾼다. 이전 미공개 tag는 `refs/archive/v0.9.0-pre-close-20260910`에 보존했다.

새 agent `4316965a…`와 drive `44cc9226…`는 버전 0.9.0 소스에서 재빌드했다.
clean 소스의 smoke·2B pressure·35B r96은 모두 완료/해제/idle UNLOAD 통과. r256 `20260909T192319Z-f82b070a`는
Windows Update의 계획 재시작으로 중단돼 512/0/0이며, 출력 16,896 token과 최초 오류/cleanup_error가 보존됐다.
새 바이너리의 must_refuse는 아직 실행하지 않았다. 구체적인 Windows 이벤트 XML·실행 ID·전체 해시는
[게이트 증거](../../layers/adapters/llamacpp/staged/scripts/validation/evidence/2026-09-10-release-gate-v0.9.0.md)가 소유한다. 원격 이미지 권위는 `evidence.remote.images`이며 generic server 해시는 기존 로컬 cache다.

로컬 `F:/dev/p4-releases/v0.9.0/`, 원격 `C:/Users/42mob/p4-remote/releases/v0.9.0/`에
`p4-v0.9.0-candidate-windows-x64-cuda.zip`, `p4-v0.9.0-candidate-source.zip`,
`p4-v0.9.0-candidate-evidence.zip`, `RELEASE-STATUS.json`·`SHA256SUMS`를 보관한다.
실행 파일·CUDA DLL·라이선스, 현재 소스, 10개 실행의 원자료 및 실패/성공 로그를 실제로 포함한다.
모델 가중치는 포함하지 않는다. 압축물 외부 SHA256과 runtime/evidence 내부 `Verify.ps1`로 확인한다.
manifest 묶음 총합은 `e57b49a793512aba19328b0c6876687221def3fe8096cef09c58b6d1d932d959`다.

현재 원격 agent/stage는 정지 상태이며 이전 배포 백업을 유지한다. OS/driver/로그인 정책은 변경하지 않았다.
**필요한 외부 입력은 42mob Windows 로그인 복구**다. 이후 파일 해시 확인 → r256·must_refuse 판정 →
증거 갱신 → annotated v0.9.0 봉인 순서만 남았다. 다음 버전의 기능 개발은 이번 마감에 추가하지 않는다.

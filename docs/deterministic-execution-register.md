# Deterministic execution register

This document is an active register that reuses facts learned from repeated runs as up-front blocks for the next stage. Historical reports
own the original evidence; this register owns only the lessons still in force and the pre-run checks. It does not merely record that
an error happened. Every entry carries its root-cause evidence, its automatic block path and its reuse point together.

When a new failure is observed, finish the following procedure within the same change.

1. Preserve the raw logs and the source/binary/input identity in the report.
2. Pin the disproven hypothesis and the causal boundary in one sentence, and assign a new ID.
3. Instead of a caution that people have to remember, add a preflight, an assertion, a unit test or a real consumption-path test.
4. Open a new round only after the next execution plan references that ID and its block path.
5. Confirm that a mutation removing the blocking mechanism lets the original failure through again. If this could not be run, mark the entry as planned rather than in force.

Do not delete resolved entries at the end of a stage. Only when the product path has disappeared or been replaced by a stronger check,
record the status and the replacing ID. Do not copy report figures or the HEAD of the time into this register and use them as the latest execution evidence.

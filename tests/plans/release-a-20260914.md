1. A0 / A-RED: run the baseline tests specified in the plan: timer alone, scheduler, bounded_strategy, service_budget,
   model-loading and cluster composer. Distinguish the linearization points of the timer wait and a normal RELEASE.
   Even if the test synchronization is changed, keep the request/flight/slot/input authority preservation oracle,
   and check a RELEASE forcibly interleaved in a real Worker and an independent mutation that corrupts timer authority.
2. A0 / A-COST: pin the hash, source/binary, inputs, first error and cleanup errors of the original 100,038-token×8 failure and of the mixed run that never started.
   The 550B original is preserved as failure evidence, and re-running it first is not required for the new target. Analyze Qwen's new
   stage execution/return times, but do not fill missing stage time with compute.
   Write a strict manifest and replay command for the normal corpus, correct answers, tokenization, arrivals, deadlines, SLO and resources/identity.
   If the cost lower bound exceeds the SLO, record the required changes/resources and follow the contract's stop condition.
3. A1 / A-PLAN: on the public OUTER input → native PLAN → LOAD → actual allocation path, verify rejection of capacity, shared-pool, cut and artifact/ABI mismatches,
   and reclaim of partial creation. Do not re-implement the existing planner.
4. A2 / A-LIFE: connect real user submit/query/cancel/drain/UNLOAD/cold recovery to the event path.
   Independently confirm committed output, no publishing after cancel, stage quiescence, held completion and old generations.
5. A3 / A-BYTES: bind the separately owned costs of input, result and receipt, and their combined limit, to the real consumption path.
   At boundary ±1, Full/Closed, and duplicate/late results, preserve the ledger, reservations, credit and output authority.
6. A4 / A-BATCH/A-COST: verify the existing policy's request/session fairness, publishing/settlement and next wave on the real worker/native.
   Do not dodge failing inputs by enlarging G2/G5 or changing defaults. Require an independent removal mutation for each fix.
7. A5 / A-SERVICE: seal the current source/native/DLL/model/corpus, and run cold/sustained/recovery/overload/fault according to the A contract and H0–H7.
   Release requires normal EOS, correct answers, release of every stage and the SLO to be met, all together.

## Rounds and records

Each fix bundle gets at most 3 rounds: baseline counterexample and cause confirmation, fix plus removal mutation, and sealed final confirmation.
Do not repeat runs without an identified common cause, and do not relax normal inputs, limits, correct answers or the SLO. Environment checks before preparation are kept distinct from execution arms.
At the end of each phase, report and commit the source, test IDs, full commands, exits, passed/failed/ignored/not run, causes and remaining work.
The full Rust tally uses the final exit and all summaries of `cargo test --workspace --no-fail-fast`, and HF feature regressions are also preserved.
Native and real multi-host verification is kept distinct from unit and fake-stage results. If resources are missing or the measured lower bound exceeds the contract, state explicitly that the work is incomplete.

## 환경과 전제

7물리 host/8stage의 과거 입력을 사용한다. 실제 fleet/가용량은 읽기 감사 후 새 namespace로 검증한다.
이전 agent/native 프로세스는 새 시험 소유가 아니다. 과거 `target/nemotron550-all-fleet/`를 덮어쓰지 않는다.
새 증거는 `target/release-a-20260914/`에 쓰고 tracked corpus/manifest/runner와 결속한다. 이 범위에는 UI가 없다.

## 단계와 기대값

1. A0 / A-RED: 계획에 지정된 timer 단독·scheduler·bounded_strategy·service_budget,
   model-loading·cluster composer 기준 시험을 실행한다. timer 대기와 정상 RELEASE의 선형화 지점을 구분한다.
   시험 동기화를 수정하더라도 request/flight/slot/input authority 보존 oracle은 유지하며,
   실제 Worker에서 강제로 interleave한 RELEASE와 timer 권한 오염 독립 변이를 검사한다.
2. A0 / A-COST: 원본 100,038-token×8 실패와 mixed 미시작의 hash·source/binary·입력·첫 오류·cleanup 오류를 고정한다.
   실제 stage 실행/반환 시간을 분석하되 누락된 stage 시간을 compute로 채우지 않는다.
   정상 corpus·정답·tokenization·도착·deadline·SLO·자원/identity의 엄격한 manifest와 재생 명령을 작성한다.
   비용 하한이 SLO를 넘으면 필요한 변경/자원을 기록하고 계약의 중단 조건을 따른다.
3. A1 / A-PLAN: 공개 OUTER 입력→native PLAN→LOAD→실제 allocation 경로에서 가용량·공유 pool·cut·artifact/ABI mismatch
   거부와 부분 생성 회수를 검증한다. 기존 planner를 다시 구현하지 않는다.
4. A2 / A-LIFE: 실제 사용자 제출/조회/cancel/drain/UNLOAD/cold recovery를 event 경로에 연결한다.
   commit된 출력·취소 뒤 발행 금지·stage quiescence·held completion·옛 generation을 독립적으로 확인한다.
5. A3 / A-BYTES: 입력/결과/receipt의 별도 소유 비용과 합산 한도를 실제 소비 경로에 결속한다.
   경계±1, Full/Closed, duplicate/late 결과에서 원장·예약·credit·출력 권한을 보존한다.
6. A4 / A-BATCH/A-COST: 기존 정책의 request/session 공정성·발행/정산·다음 wave를 실제 worker/native에서 검증한다.
   G2/G5 확대나 기본값 변경으로 실패 입력을 회피하지 않는다. 각 수정에 독립 제거 변이를 요구한다.
7. A5 / A-SERVICE: 현재 source/native/DLL/model/corpus를 봉인하고 A 계약과 H0–H7에 따라
   cold/sustained/recovery/overload/fault를 실행한다. 정상 EOS·정답·모든 stage 해제·SLO를 모두 만족해야 출시다.

## 라운드·기록

각 수정 묶음은 기준 반례/원인 확인, 수정 및 제거 변이, 봉인 최종 확인의 최대3라운드다.
같은 원인 없이 반복하거나 정상 입력/상한/정답/SLO를 완화하지 않는다. 준비 전 환경 점검은 실행 arm과 구분한다.
각 단계 종료 때 소스·시험 ID·전체 명령·exit·passed/failed/ignored/미실행·원인·남은 작업을 보고하고 커밋한다.
전체 Rust 집계는 `cargo test --workspace --no-fail-fast` 최종 종료와 모든 summary를 사용하며 HF feature 회귀도 보존한다.
native·실제 여러 host 검증은 단위/가짜 stage 결과와 구분한다. 자원이 없거나 측정 하한이 계약을 넘으면 미완을 명시한다.

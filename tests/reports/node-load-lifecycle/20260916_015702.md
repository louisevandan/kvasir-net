# LOAD·UNLOAD M1 typed adapter completion 검증

2026-09-16 KST. 기준 source는 `1b407b32456d4b047d1e6edd149b942d2fe83fba`이며 원격 검증 host는
Spark `m42@192.168.0.26`이다. 이 PC에서는 build/model run을 하지 않았다. 판정은 **typed 경계 GREEN,
M1 전체 IN_PROGRESS**다. agent supervisor와 실제 TCP neutral LOAD/UNLOAD는 아직 구현·검증하지 않았다.

## 구현 계약

`RetainedNodeAdapter::decode_lifecycle_completion`은 adapter가 자기 결과를 typed 상태로 해석하는 읽기 전용
경계다. 기본 구현은 성공을 추정하지 않는다. ordinary completion front는 계속 EventNode만 dequeue하며,
agent supervisor는 broker가 bounded agent input으로 전달한 Event를 원 요청과 대조한 뒤 이 API를 호출한다.

`AdapterLifecycleCompletion`은 operation, status, resource state, first/cleanup error를 분리한다. 성공 LOAD는
Present, 성공 UNLOAD는 Absent이고 두 오류가 모두 없어야 한다. Rejected/Failed에는 비어 있지 않은
first error가 필요하다. 이 값만으로 route 제거·Event retire·native cleanup 성공 권한을 주지 않는다.

기존 격리 검증 복사본에 전달한 뒤 다음을 실행했다.

```text
CARGO_BUILD_JOBS=8 RUST_TEST_THREADS=8 /home/m42/.cargo/bin/cargo test --locked -p p4-adapter --jobs 8
```

결과는 unit 112 passed / 0 failed / 0 ignored, doc-test 1 passed, exit 0이다. 완성 후보의 표적 코드 gate는
첫 실행에 통과했다. 이는 M1 실제 agent 경로나 llama.cpp/HF worker 완료 증거가 아니다.

## 독립 변이

검증 commit으로 별도 worktree `/home/m42/p4-m1-mut-1b407b324`와 별도 target을 만들었다. 성공 LOAD에서
`ResourceState::Present` 증명을 제거하고 다른 arm은 유지했다. 최종 변이 diff는 해당 match arm만
`Err(...)`에서 `Ok(())`로 바꿨고 `cargo check --locked -p p4-adapter --jobs 8`이 통과했다.

표적 시험은 exit 101로 실패했다.

```text
node_adapter::tests::node_load_lifecycle_typed_completion_never_infers_success_from_snapshot_or_errors
left: Ok(())
right: Err("successful LOAD completion must prove present resources")
```

따라서 문법 오류나 stale binary가 아니라 성공 resource 증명 제거를 시험이 검출했다.

## 준비 실패와 승격한 교훈

코드 baseline은 첫 실행 통과였지만 문서·변이 준비에는 네 종류의 사전 검토 누락이 있었다. 이를 숨겨
전체 절차가 첫 시도였다고 보고하지 않는다.

- mixed EOL과 잘못 인용한 정규화가 대형 문서를 한 줄로 합쳤다. 공개된 잘못된 commit은 force push하지
  않고 부모 원문 대비 112줄 추가·삭제0인 전진 복구 commit `8a7cdb81a`로 바로잡았다 (`L006`, `L007`).
- PowerShell/SSH/Python 중첩 인용은 원격 도달 전 실패했다. 별도 변이 script 전달로 교체했다 (`L009`).
- 원격 origin이 임시 bundle이어서 새 commit 약칭이 없었다. 검증 bundle의 전체 `FETCH_HEAD` hash를
  확인한 뒤 worktree를 만들었다 (`L010`).
- 첫 변이 교체문은 쉼표 누락으로 compile error였으므로 변이 검출에서 제외했다. 문법을 고친 뒤
  `cargo check`를 통과시켰다 (`L011`). Spark toolchain에는 rustfmt가 없어 설치하지 않고 local baseline
  fmt와 remote mutation check를 분리했다 (`L012`).

다음 첫 행동은 같은 mailbox front의 추가 소비자를 만들지 않는 agent supervisor state machine과
neutral actual TCP `NL04/NL02/NL10/NL07/NL01` 묶음을 완성한 뒤 원격 첫 gate를 여는 것이다.

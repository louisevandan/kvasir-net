## Implementation contract

`RetainedNodeAdapter::decode_lifecycle_completion` is a read-only boundary through which an adapter interprets its own result as a typed state.
The default implementation does not presume success. The ordinary completion front is still dequeued only by EventNode,
and the agent supervisor calls this API after matching the Event that the broker delivered as bounded agent input against the original request.

`AdapterLifecycleCompletion` keeps operation, status, resource state and first/cleanup error separate. A successful LOAD is
Present, a successful UNLOAD is Absent, and both must carry no errors. Rejected/Failed require a non-empty
first error. This value alone grants no authority for route removal, Event retirement or native cleanup success.

## Preparation failures and lessons promoted

The code baseline passed on the first run, but document and mutation preparation had four kinds of missed pre-review. These are not hidden
by reporting the whole procedure as a first attempt.

- Mixed EOL and a wrongly quoted normalization merged a large document into one line. The published bad commit was not force-pushed;
  it was corrected by the forward-fix commit `8a7cdb81a`, with 112 lines added and 0 deleted relative to the parent's original (`L006`, `L007`).
- Nested PowerShell/SSH/Python quoting failed before reaching the remote. It was replaced by transferring a separate mutation script (`L009`).
- The remote origin was a temporary bundle, so the new commit's short hash did not resolve. The worktree was created after confirming the full
  `FETCH_HEAD` hash of the verification bundle (`L010`).
- The first mutation replacement was a compile error because of a missing comma, so it was excluded from mutation detection. After the syntax was fixed,
  `cargo check` passed (`L011`). The Spark toolchain has no rustfmt; instead of installing it, the local baseline
  fmt and the remote mutation check were kept separate (`L012`).

The first next action is to complete the agent supervisor state machine, without creating an additional consumer of the same mailbox front, and the
neutral actual-TCP `NL04/NL02/NL10/NL07/NL01` bundle, and then open the first remote gate.

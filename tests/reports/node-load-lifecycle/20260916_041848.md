## Implementation verdict

- Rust event-drive creates nodes with an Agent-target `NODE_LOAD`, with no separate CREATE/DELETE, and
  removes them with the typed `succeeded/absent` of `NODE_UNLOAD`. Multiple results with the same Agent source are
  bound to the requesting node by causation ID, and then node/generation/adapter/content identity is checked again.
- If one of several LOADs is rejected, OUTER individually UNLOADs only the nodes that already succeeded. The first failure and cleanup failures are
  kept separate, and a node that did not succeed is not recorded as a successful reclaim.
- The HF Qwen controller and the lifecycle verifier send both normal UNLOAD and unknown-state abort through the Agent
  lifecycle. Direct command bypasses are rejected, and `owned`/`ready` are removed only by typed resource state.
- The legacy CREATE/DELETE acceptance branch in the Agent event runtime was removed. Searching the normal product path finds
  no old content type; the two strings remain only in the no-effect rejection tests.
- The HF control-plane import does not require the model package. safetensors is loaded only in the actual tensor `step`,
  and this boundary is pinned by an `-I -S` isolated import counterexample.

## Actual current path

On the product event path, `entrypoints/agent/src/event_runtime/control.rs` receives an agent-target CREATE,
builds the mailbox and adapter, registers the broker route and then starts the `RetainedEventNode` task. That node task
forwards adapter-target LOAD/UNLOAD to the adapter, and the broker sends adapter completions directly to OUTER.
DELETE comes back into agent control, which checks generation, the admission fence, the adapter snapshot and input/completion drain,
then removes the route and the `NodeOwner`.

The target contract's LOAD/UNLOAD is therefore not a simple rename of the existing CREATE/DELETE. At the time of the LOAD request there is no node
route, and the source of the final lifecycle result must be the agent, not the removed node. If the agent control task
awaits a long adapter LOAD, INSPECT, other node lifecycle commands and transport reconcile on the same agent are blocked.

The actual current callers are Rust `tools/event-drive/src/run/{mod.rs,load.rs}` and HF
`layers/adapters/hf/scripts/verification/lifecycle/run.py`. `ToAgent::CreateNode/DeleteNode` in `layers/service` and
`layers/agent::Agent::create_node/delete_node` are a separate service path. Do not confuse this with migrating the product event callers
and make deleting that entire legacy API a prerequisite for M1.

## M1 implementation boundary

1. Put a common lifecycle metadata codec and agent-target LOAD/UNLOAD/result content types in the protocol layer.
   The protocol does not interpret opaque adapter bytes.
2. Leave only a short precheck and owner occupancy in the control task. Run the `loading|loaded|unloading|failed` supervisor
   as a per-node task, and have the agent own sending the terminal result and preserving failures.
3. Give `RetainedNodeAdapter` a typed lifecycle completion boundary separate from the snapshot string. Ordinary adapter
   completions and the lifecycle terminal must not take each other's mailbox front.
4. LOAD checks the common metadata and retained capacity, builds the adapter, registers the broker route and delivers the opaque
   load exactly once. If it fails after registration, remove or quarantine according to the typed resource state.
5. UNLOAD, after the admission fence, does not wait on adapter busy/terminal; the supervisor tracks it. Only when typed success,
   input/output drain and worker cleanup are all true does it remove the route and owner and send the agent-owned result.
6. The agent lifecycle result also consumes the existing bounded completion/transport receipt budget. Do not create a separate unbounded channel or
   duplicate the original Event.

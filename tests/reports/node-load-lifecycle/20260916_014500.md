## 실제 현재 경로

제품 event 경로는 `entrypoints/agent/src/event_runtime/control.rs`가 agent-target CREATE를 받아
mailbox와 adapter를 만들고 broker route를 등록한 뒤 `RetainedEventNode` task를 시작한다. adapter-target
LOAD/UNLOAD는 그 node task가 adapter에 전달하고 adapter completion은 broker가 OUTER로 직접 보낸다.
DELETE는 다시 agent control로 들어와 generation, admission fence, adapter snapshot, input/completion drain을
확인한 뒤 route와 `NodeOwner`를 제거한다.

따라서 목표 계약의 LOAD/UNLOAD는 기존 CREATE/DELETE의 단순 이름 변경이 아니다. LOAD 요청 당시 node
route가 없고, 최종 lifecycle 결과의 source는 제거된 node가 아니라 agent여야 한다. agent control task가
긴 adapter LOAD를 await하면 같은 agent의 INSPECT·다른 node 수명 명령·transport reconcile가 막힌다.

현재 실제 호출자는 Rust `tools/event-drive/src/run/{mod.rs,load.rs}`와 HF
`layers/adapters/hf/scripts/verification/lifecycle/run.py`다. `layers/service`의 `ToAgent::CreateNode/DeleteNode`와
`layers/agent::Agent::create_node/delete_node`는 별도 service 경로다. 제품 event 호출자 이관과 혼동해
그 legacy API 전체 삭제를 M1 선행 조건으로 만들지 않는다.

## M1 구현 경계

1. protocol layer에 공통 lifecycle metadata codec과 agent-target LOAD/UNLOAD/result content type을 둔다.
   opaque adapter bytes는 protocol이 해석하지 않는다.
2. control task에는 짧은 사전검사와 owner 점유만 남긴다. `loading|loaded|unloading|failed` supervisor를
   node별 task로 실행하고 terminal 결과 전송·실패 보존을 agent가 소유한다.
3. `RetainedNodeAdapter`에 snapshot 문자열과 별개인 typed lifecycle completion 경계를 둔다. 일반 adapter
   completion과 lifecycle terminal이 서로의 mailbox front를 빼앗지 않게 한다.
4. LOAD는 common metadata와 retained capacity를 검사하고 adapter를 만든 뒤 broker route를 등록해 opaque
   load를 정확히 한 번 전달한다. 등록 뒤 실패하면 typed resource state에 따라 제거 또는 격리한다.
5. UNLOAD는 admission fence 뒤 adapter busy/terminal을 기다리지 않고 supervisor가 추적한다. typed 성공,
   input/output drain과 worker cleanup이 모두 참일 때만 route와 owner를 제거하고 agent-owned 결과를 보낸다.
6. agent lifecycle 결과도 기존 bounded completion/transport receipt 예산을 소비한다. 별도 무제한 channel과
   원 Event 복제를 만들지 않는다.

## M1 첫 시험 순서

첫 완전 gate 전에 NL04 malformed/±1·unsupported kind의 factory/native 효과 0, NL02 동시 같은 ID 수락 1,
NL10 느린 neutral LOAD 중 INSPECT 응답, NL07 held terminal에서 조기 삭제 0을 실제 agent TCP 경로로 먼저
고정한다. 그 뒤 정상 neutral LOAD→요청→UNLOAD에서 CREATE/DELETE 없이 final nodes 0과 agent source
lifecycle result를 확인한다. adapter별 llama.cpp/HF 실제 worker 연결은 M2에서 수행한다.

이번 B5에서 관찰한 dynamic-port bind 실패 뒤 native stdin join 대기는 NL05/NL08의 실제 실패 fixture로
재사용한다. 모델 실행 전에 `tools/validate_event_runtime_preflight.py`가 동적 포트 충돌과 잔존 native를
거부한다. native 자체의 bind-failure 종료 보강은 M2 llama cleanup 시험에 포함한다.

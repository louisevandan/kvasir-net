# LOAD·UNLOAD 노드 수명 M4 수용 보고

## 판정

M4 범위는 **GREEN**이다. 외부 CREATE/DELETE 없이 Agent-target NODE_LOAD가 실제 llama.cpp/HF
노드를 만들고, NODE_UNLOAD 성공 뒤 adapter 자원·worker·route·NodeOwner가 사라지는 경로를
실제 모델과 두 물리 agent에서 확인했다. llama.cpp의 정상 생성·재적재·부분 LOAD 실패 회수와
HF의 순차 요청·교차 실행·취소·이전 generation 거부·새 worker 재적재가 통과했다.

이 결과는 작은 Qwen3.5-0.8B 수명 conformance다. Qwen3.5-122B-A10B의 H0–H7,
장문 정상 서비스, 강한 8-wave, SLO와 성능 승격은 포함하지 않는다.

## 결정론적 실행 판정

`first_pass=fail`이다. 기대값이나 입력을 완화하지 않았고 각 실패 뒤 같은 명령을 반복하기 전에
원인과 차단 수단을 `L040`–`L051`에 추가했다.

- L1, L2, H1은 첫 실제 arm에서 통과했다.
- L3는 실제 adapter 오류 content-type과 실패 뒤 FINISH 누락을 발견했고, 한정 수정 뒤 통과했다.
- H2의 첫 준비물은 파일명과 달리 short scenario였으므로 H2 증거로 세지 않았다. scenario를 실행 전/후
  파싱하는 차단을 추가한 실제 H2가 통과했다.
- H3 첫 실행은 제품이 정상적으로 bridge에서 이전 generation을 거부했지만 검증기가 Python worker
  오류를 기대했다. 소유 경계를 대조해 정규화된 bridge 결과를 고정한 2차 H3가 통과했다.
- 변이와 workspace runner는 비대화형 SSH의 rustup/nvm PATH 누락으로 각각 시험 전 한 번 중단됐다.
  Cargo와 Node 절대 경로를 사전 검사한 새 clone/target의 2차 실행이 통과했다.
- 최종 상태 문서 patch는 이미 있던 L006을 즉시 적용하지 않아 7개 CRLF 문서가 mixed EOL로 거부됐다.
  byte 단위 정규화와 line count/numstat 대조를 적용하고 문서 gate를 다시 통과했다.

각 개별 봉인 gate는 최대 2회 안에 닫혔다. M4 전체의 첫 완전 후보는 환경/runner 전제까지 한 번에
닫지 못했으므로 첫 실행 성공 목표에는 미달했다. 이 사실을 후속 H0 preflight의 필수 입력으로 유지한다.

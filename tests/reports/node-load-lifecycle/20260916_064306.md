# LOAD/UNLOAD node lifecycle M4 acceptance report

## Verdict

The M4 scope is **GREEN**. With no external CREATE/DELETE, an Agent-target NODE_LOAD creates real llama.cpp/HF
nodes, and after a successful NODE_UNLOAD the adapter resources, worker, route and NodeOwner disappear; this path was
confirmed with real models on two physical agents. For llama.cpp, normal generation, reload and cleanup after a partial LOAD
failure passed; for HF, sequential requests, interleaved execution, cancellation, rejection of a previous generation and
reload into a new worker passed.

This result is lifecycle conformance on the small Qwen3.5-0.8B. It does not include H0–H7 for Qwen3.5-122B-A10B,
long-form normal service, the strong 8-wave, SLO or performance promotion.

## Deterministic execution verdict

`first_pass=fail`. Expected values and inputs were not relaxed, and after each failure the cause and the blocking measure
were added to `L040`–`L051` before repeating the same command.

- L1, L2 and H1 passed on their first real arm.
- L3 found the real adapter error content-type and a missing FINISH after failure, and passed after a scoped fix.
- The first prepared input for H2 was, despite its file name, a short scenario, so it was not counted as H2 evidence. The
  real H2, with a block that parses the scenario before and after the run, passed.
- On the first H3 run, the product correctly rejected the previous generation at the bridge, but the verifier expected a
  Python worker error. The second H3, which pins the normalized bridge result after checking the ownership boundary, passed.
- The mutation and workspace runners each stopped once before testing because non-interactive SSH lacked the rustup/nvm
  PATH. Second runs in a new clone/target, with the Cargo and Node absolute paths prechecked, passed.
- The final status document patch did not immediately apply the existing L006, so 7 CRLF documents were rejected for
  mixed EOL. Byte-level normalization and a line count/numstat comparison were applied, and the documentation gate passed again.

Each individual sealed gate closed within at most 2 attempts. The first complete M4 candidate did not close everything
including environment/runner preconditions in one go, so it fell short of the first-run success goal. This fact is kept
as a required input for the subsequent H0 preflight.

## Implementation verdict

- The llama.cpp actual retained worker executes LOAD/UNLOAD from Agent lifecycle Events and returns a typed terminal
  to the Agent. The first blocking input and the following drain use the same retirement path.
- llama.cpp start failures and UNLOAD failures distinguish `Absent` from `Unknown` according to the native cleanup result, and
  preserve the first error and the cleanup error.
- HF separates the supervisor Agent from the OUTER owner of inference. It binds the real Python child's LOAD/UNLOAD results
  to the typed terminal and includes the retained native response volume in the retention snapshot.
- Both adapters retire the lifecycle input claim before publishing the terminal. If the completion store is full, they wait before any native
  effect and preserve the original input.
- HF reserves 512 bytes of typed wrapper headroom along with the Python frame, before any native effect. Python responses stay within
  the 1,024-byte limit, and even a real child UNLOAD whose combined result with the wrapper exceeds it does not lose the Agent terminal.

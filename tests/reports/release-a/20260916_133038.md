## Executed Steps

1. I0-S/M/L을 한 LOAD에서 `case-00`, `case-04`, `case-06` 순으로 실행하는
   `execution_groups.I0` 계약을 추가했다. 요청별 deadline은 600,000/1,200,000/1,800,000ms,
   전체 timeout은 그 합과 300,000ms 회수 여유를 더한 3,900,000ms다.
2. `prepare-integrity-i0.py`가 기존 H1 corpus/oracle materializer의 산출물에서 세 case만 선택하고
   `max_in_flight=1`, LOAD/UNLOAD 각 1회의 seal을 만든다.
3. event-drive 요청 산출물에 `eligible_ms`, `send_started_ms`, `send_completed_ms`, `release_ms`를
   추가했다. 다음 요청 eligibility가 이전 RELEASE보다 앞서는 실행은 I0 judge가 거부한다.
4. `judge-integrity-i0.py`가 원시 artifact, seal, GPU 표본, 자원 snapshot, 분산 실행 증거와 cleanup을
   artifact/config hash로 결속한다. head scheduler phase와 세 stage span 통계를 분리해 계산한다.
5. Spark에서 formatter와 `p4-event-drive` 전체 시험을 제한 build로 실행했다.

## Failures

원격 첫 formatter 검사는 assertion 한 줄의 rustfmt 줄바꿈 차이를 검출했다. 제품 의미나 시험 단언은
바꾸지 않고 rustfmt가 제시한 정확한 줄바꿈만 적용했다. 두 번째 실행에서 formatter와 Rust 시험 전체가
통과했다.

I0 원시 judge의 첫 self-test에서는 GPU 표본 하나를 제거한 변이가 bundle 생성 단계에서 수용됐다.
최종 judge는 이를 거부할 수 있었지만 중간 산출물도 실패 폐쇄형이어야 하므로 원시 judge에 95% coverage
하한을 추가했다. 수정 뒤 해당 변이를 포함한 8종이 모두 거부됐다. 이 교훈은 L072에 고정했다.

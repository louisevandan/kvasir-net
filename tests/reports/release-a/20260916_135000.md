## Executed Steps

1. event-drive artifact에 monotonic 상대 시간과 함께 `started_unix_ms`를 기록했다. 원격 GPU 표본을
   다른 실행에서 가져와 상대 시간만 맞추는 경우를 거부할 수 있게 했다.
2. `build-integrity-i0-evidence.py`를 추가했다. artifact/config hash, 세 host 순서, 1초 표본 grid,
   절대 capture 시각 750ms 허용차, 95% coverage, 네 자원 snapshot의 정확한 상태, 분산 실행과 최종
   cleanup을 독립 검사한다.
3. integrity spec에 제품의 결정론적 상태기계, 고정 seed/schedule, fault별 요청 index·output ordinal·
   stage·generation·delay를 봉인했다. 시험은 알고리즘 탐색이 아니라 이 사전 계약의 증명 절차다.
4. 세 원격 host에서 고정 source bundle을 clean checkout하고 CPU 70% 이하의 job 수로 release binary를
   다시 만들었다. 새 inspector를 동일 hash로 전송해 source, binary, native dependency, host/device,
   link, telemetry와 보호 agent 상태를 다시 읽었다.
5. H0 v4가 runtime, 원격 binary/library, model/layout, corpus, materializer, raw evidence builder와 judge를
   hash로 결속하도록 생성하고 통합 verifier를 실행했다.

## Failures

최초 설계 검토에서 event-drive artifact와 원격 GPU 표본이 상대 시간만 공유해 다른 실행의 표본을
결합할 수 있는 틈을 확인했다. 모델 실행 전에 runtime absolute anchor와 두 단계 시각 검사를 추가해
L073으로 고정했다. 이는 모델 trial이 아니라 실행 전 계약 감사에서 검출한 결함이다.

Spark의 비대화형 직접 검증 명령 한 번은 Cargo PATH가 없어 시험 시작 전에 종료됐다. L050에 따라
고정 Cargo 경로를 사용한 뒤 formatter와 동일 Rust 시험이 통과했다. 제품 실행이나 모델 LOAD 회차로
세지 않는다.

## Reproducibility

```text
python test/benchmarks/cluster-inference/release-a/verify-h0-v4.py
```

결과는 `load_authorized=true`, `runtime_acceptance=false`, `integrity_baseline=false`,
`performance_improvement_claimed=false`다. H0는 I0 실행 입력과 증명 절차를 봉인했을 뿐 서비스 무결성을
승인하지 않는다. 다음 단계는 새 task agent의 양방향 INSPECT와 정확한 pre-LOAD 상태를 통과한 뒤,
I0-S/M/L을 고정 순서로 한 LOAD에서 한 번 실행하는 것이다.

# Release A I0 wrong-answer verdict boundary fix and the remaining product cause

2026-09-16 18:05 KST. This record follows up the [6-cause separation diagnosis](20260916_172000.md).

## Verdict

The exact-arithmetic failure of Qwen3.5-122B UD-Q5_K_S was reproduced
even on a single host with a short calculation input. There is no evidence that the P4 transport altered the computation. Separately, the OUTER runner
checked only EOS and length and passed the independent corpus oracle only to the final judge, so
even a wrong JSON answer could be recorded as `artifact.passed=true`. This verdict gap has been
fixed. **This does not fix the model's generation of wrong answers, or tokens already transmitted.**
I0 is still RED, and no new distributed LOAD is allowed.

## Changes and verification boundary

- `ResponseExpectation.expected_json` parses and compares each request's JSON value.
  It ignores only object key order and whitespace, and preserves array order, values and types. Wrong numbers and
  code fences are rejected as a mismatch and as invalid JSON, respectively.
- The H1 materializer binds the oracle, generated and hash-verified separately from the raw data, to
  every request in the OUTER configuration. The I0 materializer selects and inherits that per-request configuration.
  The final independent judge and the oracle were not changed.
- This check changes the OUTER's run result `passed`. The raw generated content, EOS, RELEASE and
  their evidence remain as they were; a service contract that keeps unverified output from being exposed
  to real product callers has not been implemented.

## Remaining product fix

This change closed the *error of judging a wrong answer as a success*, but it does not make the model generate
the exact answer. For arbitrary natural-language questions, the P4 common transport layer has no authority
to know the raw data or the true values. If exact arithmetic is part of the service contract, the OUTER caller must
specify the raw data, target IDs, formula and error response, and a deterministic computing party must verify the model's
extracted values against the raw data before computing, or terminate explicitly on a mismatch.
This requires a new product API and real consumption-path tests, and I0 is not made GREEN by overwriting responses
with the current benchmark's correct answers. Distributed I0 resumes only after that contract,
single-host exact JSON 3/3 with removal mutations, and a new H0 seal.

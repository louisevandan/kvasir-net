## 판정

Qwen3.5-122B UD-Q5_K_S의 정확 산술 실패는 단일 호스트·짧은 계산 입력에서도
재현됐다. P4 transport가 계산을 변조했다는 증거는 없다. 별도로 OUTER 실행기는
EOS·길이만 검사하고 독립 corpus 오라클을 최종 judge에만 전달했기 때문에,
잘못된 JSON 답도 `artifact.passed=true`로 기록할 수 있었다. 이 판정 누락은
수정했다. **모델의 오답 생성이나 이미 전송한 token을 수정한 것은 아니다.**
I0는 여전히 RED이며 새 분산 LOAD를 허용하지 않는다.

## 변경과 검증 경계

- `ResponseExpectation.expected_json`은 요청별 JSON 값을 파싱해 비교한다.
  객체 키 순서·공백만 무시하고 배열 순서·값·형식은 보존한다. 잘못된 수치와
  코드 펜스는 각각 불일치·잘못된 JSON으로 거부한다.
- H1 materializer는 원자료에서 별도 생성·해시 검증한 oracle을 OUTER 설정의
  매 요청에 결속한다. I0 materializer는 그 요청별 설정을 선택·계승한다.
  최종 독립 judge와 oracle을 바꾸지 않았다.
- 이 검사는 OUTER의 실행 결과 `passed`를 바꾼다. 원시 생성 내용·EOS·RELEASE와
  그 증거는 그대로 남으며, 실제 제품 호출자에게 검증 전 출력을 노출하지
  않도록 하는 서비스 계약까지 구현된 것은 아니다.

## 남은 제품 수정

이 변경은 오답을 *성공으로 판정하는 오류*를 닫았지만, 모델이 정확 답을
생성하게 하지는 않는다. 임의의 자연어 질문에 대해 P4 공통 전송 계층에는
원자료나 참값을 알 권위가 없다. 정확 산술이 서비스 계약이라면 OUTER 호출자가
원자료·대상 ID·계산식·오류 응답을 명시하고, 결정론적 계산 주체가 모델의
추출값을 원자료와 검증한 뒤 계산하거나 불일치를 명시적으로 종료해야 한다.
이것은 새로운 제품 API와 실제 소비 경로 시험이 필요하며, 현재 benchmark의
정답을 응답으로 덮어쓰는 방식으로 I0를 GREEN으로 만들지 않는다. 그 계약과
단일 호스트 정확 JSON 3/3·제거 변이, 새 H0 봉인 뒤에만 분산 I0를 재개한다.

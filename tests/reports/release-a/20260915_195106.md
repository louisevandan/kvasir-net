## 실제 lifecycle 결과

기존 `:52005` agent는 변경하지 않았다. 세 물리 host에 현재 소스의 agent를 `:52150`으로 격리해 띄우고
각 agent의 INSPECT가 `nodes=[]`, adapter가 `llamacpp`와 `hf-transformers`임을 먼저 확인했다. P4 공개
event envelope로 host별 `CREATE→LOAD`를 보내 세 stage가 함께 READY인 시점을 INSPECT한 뒤
`UNLOAD→DELETE`했다. SESSION·INFERENCE는 byte 경계가 아직 승인되지 않아 보내지 않았다.

세 stage의 LOAD 시작부터 전체 READY까지 403,804ms, 최종 cleanup까지 412,404ms였다. READY 응답은

`CPU[CPU]|CUDA[CUDA0]`, Mac은 `BLAS[BLAS]|CPU[CPU]|MTL[MTL0]`였다. 이기종 파이프라인 실행 시
`physical-wire-v4` profile을 명시해야 하며 이번 단계는 요청을 만들지 않았다.

## 첫 실행 실패 원인

`first_pass=fail`이다. 첫 LOAD 명령의 local stage endpoint를 `127.0.0.1:0`으로 넣었다. 실제 소비 코드인
llama.cpp adapter `Worker::load`는 이 값을 파싱한 뒤 port와 bind를 native 자식의 `--port 0 --bind
127.0.0.1`로 그대로 전달한다. native는 세 host 모두 usage를 출력하고 종료했다. Mac의 P4 응답은
`cannot connect to stage server: Can't assign requested address (os error 49)`, Spark는 native exit2였다.
모델 tensor 읽기 전에 약 3초 만에 같은 방식으로 실패했으므로 모델 용량·GPU·전력·빌드 부하와 무관하다.

실패 node는 상태를 `failed:stage runtime initialization failed`로 보존했고 DELETE는 empty/unloaded/closed만
허용하므로 즉시 삭제를 거부했다. 이는 실패를 정상 회수로 위장하지 않는 계약이다. PID와 전체 명령행을
확인한 뒤 이번 작업의 `:52150` agent만 cold restart하여 node registry를 비웠다. 세 host에서 비어 있던
고정 loopback port53150을 선택하고 다른 필드는 바꾸지 않은 2회차가 통과했다. 실패 로그 SHA256은 Spark
`207e859ce4326e8a06b09012c6034f82cadb95502db4ffb93304f4a6cc3db9a0`, Mac20
`0411bd121b46d8fd65021ccdbc23fb368c618d56b88e964e1204f1985e528994`, Mac21
`19b5cb1569366445454ca0186c2b3ad57b58fc373fd30a4e261c242d6d54a0cf`다.

## 증거와 회수

최종 lifecycle artifact는 45,163bytes/SHA256
`6dc2c171a8d3f1425e2feef39f19c38130689ff8b67e7412dce0ebdc59b3f714`이고 `first_error=null`,
`cleanup_errors=[]`다. 실제 native 로그 SHA256은 Spark
`5fc0ac5ab117d5b24833aec3fdbe5867e5128f5985fe55283d43671e79422950`, Mac20
`d44fb791f7a0bdbe909ffa6e7639dca2f35c189211baccc10498a286d2b0db11`, Mac21
`e5ede6ac262c7eba9cfbbca4a5151aeb6559dda440ab759c80715b6cf6816951`다. 각 로그에는 정확히 하나의
`MEMORY_PLAN`과 하나의 `MEMORY_ACTUAL`이 있다.

UNLOAD 뒤 세 host의 53150 listener는 0이다. 최종 nodes=[]를 lifecycle artifact에서 확인하고 이번 작업이
소유한 agent52150도 PID/전체 명령행 검증 후 종료해 listener0으로 만들었다. 기존 agent52005는 세 host에
그대로 남겼다. 데스크톱은 모델 실행이나 빌드에 사용하지 않았다.

## Cause of the first-run failure

`first_pass=fail`. The first LOAD command set the local stage endpoint to `127.0.0.1:0`. The actual consuming code,
llama.cpp adapter `Worker::load`, parses this value and passes the port and bind unchanged to the native child as `--port 0 --bind
127.0.0.1`. On all three hosts native printed usage and exited. The P4 response on the Macs was
`cannot connect to stage server: Can't assign requested address (os error 49)`, and on Spark native exited with 2.
It failed the same way in about 3 seconds, before reading any model tensors, so it is unrelated to model size, GPU, power or build load.

The failed node preserved its state as `failed:stage runtime initialization failed`, and DELETE, which allows only empty/unloaded/closed,
rejected immediate deletion. This is the contract that keeps a failure from being disguised as a normal reclaim. After confirming the PID and the full command line,
only this work's `:52150` agent was cold-restarted to empty the node registry. The second attempt, which chose
the fixed loopback port 53150 that was free on all three hosts and changed no other field, passed. The failure log SHA256 values are Spark
`207e859ce4326e8a06b09012c6034f82cadb95502db4ffb93304f4a6cc3db9a0`, Mac20
`0411bd121b46d8fd65021ccdbc23fb368c618d56b88e964e1204f1985e528994`, and Mac21
`19b5cb1569366445454ca0186c2b3ad57b58fc373fd30a4e261c242d6d54a0cf`.

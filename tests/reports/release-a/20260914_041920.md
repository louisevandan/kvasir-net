# Release A / corpus와 엄격한 실행 명세 준비

2026-09-14 04:19 KST, Windows PowerShell. 기준 `63395e691b05f765993ac40d6823b2fe70337c49`.
[계획](../../plans/release-a-20260914.md) · [앞선 A-RED/trace](20260914_040306.md).
A0 준비 단계이며 native 비용 분해·현재 runtime 검증·A1–A5 수용은 아직 남았다.

## 실제로 검증한 경로

- `manifest.mjs`의 실제 CLI는 hash/bytes로 파일을 대조한다. 필수 artifact/ABI·상한 누락,
  잘못된 wave/길이/contract, 응답 count×최대 bytes 부족, 여러 stage가 같은 물리 pool을 중복 예약하면 거부한다.
  pool에는 native weight/state/scratch와 output/receipt/edge의 별도 저장소 소유량을 합산한다.
  합성 명세의 구조 검사 통과는 실제 native PLAN/LOAD/할당 일치의 인증이 아니며 `runtime_acceptance=false`다.
- generator의 64개 과제는 고정 도착8wave에 매번 short4/medium2/long2를 배치한다.
  short는 source function의 equality 결함 수정, 나머지는 문서 앞/중간/끝3개 기록의 사실·정수 연산 연결이다.
  실제 public llama vocabulary로 short2785–2794, medium32000, long100038 tokens를 확인했다.
  long100038+출력2048은 context102400 안이다. model tensor는 적재하지 않은 vocab-only 시험이다.
- 모든 token ID를 LE u32 binary로 저장하고 prompt·ID·oracle hash를
  [tracked corpus manifest](../../../test/benchmarks/cluster-inference/release-a/corpus-v1.json)에 보존했다.
  무의미한 padding 대신 같은 온도 미측정 사실을 두 완결 문장으로 표현해 정확한 token 수를 맞췄다.
  명세 변경은 응답 결과에 맞춰 수행하지 않았다.
- 별도 Python parser가 원문에서 record별 수치/단위를 추출해64개 oracle을 재계산했다.
  기존100038-token 원본8건은 prompt SHA와 새 probe의 token count 모두 원본과 동일했다.
  모델이 새 과제를 실제로 풀 수 있는지는 아직 검증하지 않았다.

Node 관련9tests 통과. 독립 source 복사본의 receipt 곱 상한 제거·shared pool 합산 상한 제거·
정답 대조 제거·미관측 시간을0으로 치환한4개 변이 모두 실제 assertion 실패로 검출했다.
이 체크포인트에서 Rust runtime은 변경하지 않아 앞선1451/0/7 전체 결과를 유지한다. Rust 재집계는 하지 않았다.

## source와 증거

tokenizer가 소비한 llama pin은 `434ddbbc0e30522e897670681e503b797c12b7c1`이다.

## 재현

`tokenize.cpp`를 측정할 runtime과 같은 header 및 `llama.lib`/공유 library로 빌드한다.
probe JSON에는 `tokenizer`, `runtime_directory`, `model`의 절대 경로,
`tokenizer_source_commit`과 `cases:64`를 지정한다. 해당 DLL을 실제 runtime directory에서 읽는다.
이번 정확한 compiler 명령은 `target/release-a-20260914/build-tokenize.cmd`, 입력은 `tokenizer-spec-corrected.json`이다.

```powershell
node test/benchmarks/cluster-inference/release-a/materialize-corpus.mjs target/release-a-20260914/tokenizer-spec-corrected.json target/release-a-fresh-corpus
python test/benchmarks/cluster-inference/release-a/review-corpus.py target/release-a-fresh-corpus target/release-a-fresh-review
python test/benchmarks/cluster-inference/release-a/node-mutations.py target/release-a-fresh-node-mutations
node --test test/benchmarks/cluster-inference/release-a/*.test.mjs
```

실행 가능한 제품 manifest는 아직 만들지 않았다. 현재 native PLAN에서 요구하는 모든 physical-result/receipt/edge
상한을 산출하는 경로와 현재 runtime source·모델 shard·실제 allocation 증거가 필요하다.
다음 작업은 native n_kv/계산/capture/return 비용을 실제 실행 ID에 결속하고 A0 비용 게이트를 판정하는 것이다.

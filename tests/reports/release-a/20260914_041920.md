## Paths actually verified

- The actual CLI of `manifest.mjs` checks files by hash/bytes. It rejects missing required artifacts/ABI or limits,
  wrong wave/length/contract, a response count × maximum bytes shortfall, and multiple stages double-reserving the same physical pool.
  The pool sums native weight/state/scratch and the separately owned storage for output/receipt/edge.
  Passing the structural check of a synthetic specification does not certify agreement with a real native PLAN/LOAD/allocation, and `runtime_acceptance=false`.
- The generator's 64 tasks place short 4/medium 2/long 2 in each of 8 fixed arrival waves.
  short is fixing an equality defect in a source function; the rest link facts and integer arithmetic across 3 records at the start/middle/end of a document.
  With the actual public llama vocabulary, short 2785–2794, medium 32000 and long 100038 tokens were confirmed.
  long 100038 + output 2048 fits within context 102400. This is a vocab-only test with no model tensors loaded.
- All token IDs were stored as LE u32 binary, and the prompt, ID and oracle hashes were preserved in the
  [tracked corpus manifest](../../../test/benchmarks/cluster-inference/release-a/corpus-v1.json).
  Instead of meaningless padding, the same unmeasured-temperature fact was expressed as two complete sentences to hit the exact token counts.
  The specification was not changed to fit response results.
- A separate Python parser extracted per-record values/units from the source texts and recomputed the 64 oracles.
  For the 8 existing 100038-token originals, both the prompt SHA and the new probe's token count matched the originals.
  Whether the model can actually solve the new tasks is not verified yet.

The 9 related Node tests passed. In an independent source copy, all 4 mutations (removing the receipt product limit, removing the shared pool sum limit,
removing the answer comparison, and substituting 0 for unobserved time) were detected by actual assertion failures.

## Failure and fix

On the current pin, `prepare-pipeline-upstream.mjs` failed because it classified the
`general.architecture == minimax-m3` metadata rejection code in the existing `p4_llama_compat.cpp` as a model implementation branch.
Without removing the rejection or changing the native acceptance conditions, only that metadata check was moved into compat's `model_support.cpp`.
The moved function body is identical to the original, and its SHA256 is `c1df2d1aa005332ea6ce4282cabd309e896e7e474e697b4d407138df6a7f687a`.

The isolation check allows the model name only in plain string values of that exact file. Other files, code/comments,
architecture enums, model implementation casts and private headers are still rejected. The dedicated file also rejects llama/ggml execution calls
other than public metadata queries. Actual execution and state authority stays in the existing native layer.
The native metadata rejection responsibility is now stated in the [isolation contract](../../../docs/layer-isolation-contract.md).
This change does not approve new model support or M3 MSA acceptance.

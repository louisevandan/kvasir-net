## 실패와 수정

현재 pin의 `prepare-pipeline-upstream.mjs`가 기존 `p4_llama_compat.cpp`의
`general.architecture == minimax-m3` metadata 거부 코드를 모델 구현 분기로 분류하여 실패했다.
거부를 제거하거나 native 수용 조건을 바꾸지 않고 해당 metadata 판정만 compat의 `model_support.cpp`로 분리했다.
옮긴 함수 본문은 원본과 같으며 SHA256은 `c1df2d1aa005332ea6ce4282cabd309e896e7e474e697b4d407138df6a7f687a`다.

격리 검사는 그 정확한 파일의 일반 문자열 값에만 모델 이름을 허용한다. 다른 파일, 코드/주석,
architecture enum·모델 구현 cast·private header는 계속 거부한다. 전용 파일은 공개 metadata 조회 외
llama/ggml 실행 호출도 거부한다. 실제 실행/상태 권한은 기존 native 계층에 남는다.
[격리 계약](../../../docs/layer-isolation-contract.md)의 native metadata 거부 책임을 명시했다.
새 모델 지원이나 M3 MSA 수용을 승인한 변경은 아니다.

## 변경과 관측

읽기 EOF 뒤 반환 sender가 살아 있어 슬롯을 유지하는 경로를 확인했다. 정상 half-close도 같은 EOF라서
무조건 route를 버리지 않는다. 후보는 연결 소유 FINISH(length0)→live route 분리→대기 출력 drain→
length0 ACK를 추가한다. 새 socket binding과 실패 tombstone은 유지하고, 늦은 OUTER 결과는
원본 allocation을 failure owner에 남긴다. ACK는 요청/KV/원장 정산이 아니다.

Rust driver와 HF Python 검증 호출자에 명시 종료 소비를 연결했으나 최종 수용은 실패했다.
Studio는 읽기만 했으며 취소된 모니터링 UI 지시에 따른 수정은 없다. 기존 호출자는 아직 FINISH를
보내지 않으므로 후보 agent만 교체해도 기존 fleet 포화의 영구 해결이 되지 않는다.

실패2는 `tools/event-drive/src/run/mod.rs`의 Instant import 누락이었다. import를 보완한 다음 실행은
컴파일됐지만 실패3이 발생했다. 실패3은
`run::wire::tests::explicit_finish_rejects_eof_and_preserves_unexpected_output`다.
예상 밖 frame의 첫64byte를 읽고 오류를 반환한 소비자 버퍼와 전체721byte frame을 비교해 실패했다.
실패 후 기대값 완화·입력 삭제·추가 수정/재시험은 하지 않았다. 나머지 바이트까지 어떤 소유자에
보존할지와 실패 artifact에 노출할 계약은 아직 검증되지 않았다.

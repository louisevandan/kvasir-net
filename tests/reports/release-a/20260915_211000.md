## Implementation and boundary

The llama.cpp adapter's compat patch inspects all three worst-case graphs that the context reserve builds. Cut tensors that leave
the stage are merged as aliases only when storage/view/type/shape/stride are all identical, and the descriptor count and
`ggml_nbytes` payload are summed as checked `uint64`. No llama.cpp tensor types were added to the P4 common core.

The native stage combines the measurement with physical-v4's fixed set/capsule/owner/tensor sizes and the maximum string, row and capsule counts,
using checked integers, to produce `max_physical_result_bytes`. LOAD completes only when PLAN, MEMORY_ACTUAL and READY report the same
value. The C++ encoder first validates and sizes the whole object without allocating, and if it exceeds the exact bound
it leaves the existing output unchanged as well. The Rust decoder creates the `Cursor` and its internal capacity only after checking the body length.
The real physical result production and consumption paths for both first and middle stages use the READY bound.

## Failures and causes

`first_pass=fail`. The first full native CTest was 15/16. The fixed part of the tensor descriptor had been computed as 38bytes,
but the actual wire adds the string length prefix separately, so the fixed part was 36bytes. The per-field sums of the encoder and of the independent expected value
detected the 2bytes difference immediately. After only that constant in the formula was changed to 36, 16/16 and the real Qwen LOAD
passed.

For the final binding tool, in the first command PowerShell pre-expanded Bash's `$()`, and the next command, run after CTest had passed, gave
the binary path wrongly as `build/bin/p4-staged-server`. The third used a fixed Bash script and the actual
`build/p4_staged_server`, and checked only the source SHA and binary SHA. The mutation tool's first run likewise assumed a guard string that had
not been confirmed, and the second exited before the test because Cargo was missing from the non-interactive PATH. The third run, with the actual block and
`/home/m42/.cargo/bin/cargo` pinned first, confirmed the expected failure. The only product functionality fix was the single 2bytes adjustment to the tensor
fixed part.

2026-09-15 21:10 KST. 기준 P4 HEAD는 `0f654649c`, llama.cpp upstream은
`451b89bae0c4b1dd612eb503ceace906c01ddcc9`, compat patch set은
`d8018fa8f7f44d61d23cd68496024fa296d2571c860fda988cef91a28b2572a9`다. 판정은
**B0 GREEN, A-BYTES 전체와 실제 inference 미수용**이다. 다음 gate는 B1 LOAD resource profile 결속이다.

## 구현과 경계

llama.cpp adapter의 compat patch가 context reserve 때 만드는 세 worst graph를 모두 조사한다. stage 밖으로
나가는 cut tensor를 storage/view/type/shape/stride가 모두 같은 경우에만 alias로 합치고, descriptor 수와
`ggml_nbytes` payload를 checked `uint64`로 합산한다. P4 공통 코어에는 llama.cpp tensor 타입을 넣지 않았다.

native stage는 측정값과 physical-v4의 set/capsule/owner/tensor 고정 크기, 문자열·row·capsule 최대 수를
checked integer로 합쳐 `max_physical_result_bytes`를 만든다. PLAN, MEMORY_ACTUAL, READY가 같은 값을
보고해야 LOAD가 완료된다. C++ encoder는 전체 object를 allocation 없이 먼저 검증·계산하고 exact bound를
넘으면 기존 output도 바꾸지 않는다. Rust decoder는 body 길이를 검사한 뒤에만 `Cursor`와 내부 capacity를
만든다. first/middle 실제 physical result 생산·소비 경로가 둘 다 READY의 bound를 사용한다.

## 실패와 원인

`first_pass=fail`이다. 첫 전체 native CTest는 15/16이었다. tensor descriptor의 고정부를 38bytes로
계산했지만 실제 wire는 string 길이 prefix를 별도 합산하므로 고정부가 36bytes였다. encoder와 독립 기대값의
field별 합산이 2bytes 차이를 즉시 검출했다. 식의 해당 상수만 36으로 고친 뒤 16/16과 Qwen 실제 LOAD가
통과했다.

최종 결속 도구는 첫 명령에서 PowerShell이 Bash의 `$()`를 선해석했고, 다음 명령은 통과한 CTest 뒤
바이너리 경로를 `build/bin/p4-staged-server`로 잘못 적었다. 세 번째는 고정 Bash script와 실제
`build/p4_staged_server`를 사용해 source SHA와 binary SHA만 확인했다. 변이 도구도 첫 실행은 확인 전의
guard 문자열을 가정했고, 둘째는 비대화형 PATH의 Cargo 누락으로 시험 전 종료했다. 실제 block과
`/home/m42/.cargo/bin/cargo`를 먼저 고정한 셋째 실행이 기대 실패를 확인했다. 제품 기능 수정은 tensor
고정부 2bytes 조정 한 번뿐이다.

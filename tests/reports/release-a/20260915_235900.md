# Release A A-BYTES B3/B4 수명·경계 수용

2026-09-15 23:59 KST. B3 구현 기준은 `fcd7969c459a30d9f16e21766cfb34eaf7d140cf`,
B4 최종 기준은 `40e11478894f57489c31f2354777be6e38cb6f99`다. 판정은 **B3 GREEN,
B4 GREEN, A-BYTES 전체와 실제 inference 미수용**이다. 다음 gate는 B5 양쪽 어댑터 회귀와
Qwen3.5-122B-A10B 3-host 요청·회수다.

## 구현과 소유 경계

backend 중립 `AdapterRetainedStorage`와 `AdapterRetentionSnapshot`이 adapter 내부 보존량을 공통
INSPECT에 전달한다. llama.cpp adapter는 pending request, retained completion, native response를 각각
추적하고 HF adapter는 pending input count/bytes를 소유 객체의 수명과 결속한다. transport INSPECT는
broker receipt와 hop receipt, 실제 연결별 outstanding event/bytes/limit를 서로 다른 필드로 보고한다.

destination broker는 실제 Event 비용을 예약한 뒤만 commit한다. source는 원격 `AcceptedExact` receipt를
받기 전까지 원본과 claim을 유지하고, 결과 불명이나 receipt 부재는 quarantine으로 남긴다. 기존
`dde0813fb`의 요청별 반환 문맥과 충돌하지 않으며 같은 event runtime의 반환 경로를 보존한다.

B4에는 실제 first worker response decoder가 profile의 physical result 상한을 적용하는 반례를 추가했다.
count와 byte, native response와 completion, broker receipt와 hop outstanding을 하나의 행 수나 wire frame
한도로 합치지 않았다.

## 종료 사고와 정책 수정

`first_pass=fail`이다. B3 첫 표적 실행은 LOAD를 우회한 fixture가 TOKENIZE 선행 상태를 만들지 않아
실패했고, 소비 경로에 맞춘 fixture를 보강한 뒤 최종 workspace 두 gate가 통과했다. B4 첫 완전 gate는
이 PC에서 독립 cold build 네 개를 33/48 jobs로 연속 실행했다. 앞의 세 build가 23:35:48–23:39:04에
끝난 뒤 네 번째가 23:39:18 시작해 23:39:34 `p4-agent-core` 컴파일 중 로그가 끊겼고, Windows는
23:40:48 새로 부팅됐다. 이 구간에는 CUDA, 모델 LOAD, inference가 없었다.

23:40:53 Kernel-Power 41은 `BugcheckCode=0`, 모든 bugcheck parameter 0,
`PowerButtonTimestamp=0`, `LongPowerButtonPressDetected=false`, `WHEABootErrorCount=0`이다. 새 dump와
직전 WHEA/GPU/thermal 오류도 없다. 따라서 소프트웨어 crash나 모델 실행보다 연속 cold compiler 부하와
hard power loss의 상관관계가 직접적이다. PSU, 메인보드 보호, 열 중 어느 물리 원인인지는 이 기록만으로
구분하지 않는다.

33/48 affinity는 동시 CPU 수만 제한하며 rustc/LLVM의 turbo 전력이나 연속 build의 누적 열을 70%로
제한하지 못했다. 이 가정을 폐기했다. resource wrapper는 이 PC의 Build를 기본 거부한다. 사용자가 별도
비상 실행을 허가한 경우에만 최대 8 jobs를 적용하며, 이는 전력 측정값이 아니라 보수적 동시성 상한이다.
B4 기준과 네 변이는 Spark, Ubuntu, Mac20, Mac21에 나눠 다시 실행해 위 결과를 얻었다.

Mac21의 p4-agent 첫 실행은 SSH PATH에 Node가 없어 Rust 37개 통과 뒤 docs-lint만 환경 오류로 실패했다.
같은 소스와 범위를 Node가 있는 Ubuntu로 옮겨 2회차에 Rust 37개와 docs-lint 1개를 모두 통과했다.
제품 기대값이나 입력은 바꾸지 않았다.

## 다음 gate

B5는 먼저 새 agent namespace의 INSPECT와 작업 소유 node 목록을 수집하고 남은 node를 모두
UNLOAD/DELETE한다. 이후 현재 소스를 원격에서 빌드해 표적 Rust/C++/Python, workspace feature off/on,
소형 llama.cpp와 HF/Python의 생성·취소·회수·재수용을 검증한다. 마지막으로 Qwen122B 3-host에서 LOAD,
경계 초과 거부, 정상 한 요청, UNLOAD/DELETE, 최종 node/listener/native/GPU 점유 0을 같은 봉인으로
확인한다. 설치 앱의 `S:\models` 접근은 SSH 경로와 별도로 취급한다.

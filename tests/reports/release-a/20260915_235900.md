## Implementation and ownership boundaries

The backend-neutral `AdapterRetainedStorage` and `AdapterRetentionSnapshot` deliver the adapter's internally retained amounts to the common
INSPECT. The llama.cpp adapter tracks pending requests, retained completions and native responses
separately, and the HF adapter binds pending input count/bytes to the lifetime of the owning object. Transport INSPECT
reports broker receipts, hop receipts, and per-connection outstanding events/bytes/limit in distinct fields.

The destination broker commits only after reserving the actual Event cost. The source keeps the original and its claim until it
receives the remote `AcceptedExact` receipt, and leaves an unknown result or a missing receipt in quarantine. This does not conflict with
the per-request return context of the existing `dde0813fb` and preserves the return route of the same event runtime.

B4 added a counterexample in which the real first worker response decoder applies the profile's physical result cap.
Count and bytes, native responses and completions, and broker receipts and hop outstanding were not merged into a single row count or wire frame
limit.

## Shutdown incident and policy change

`first_pass=fail`. The first targeted B3 run failed because a fixture that bypassed LOAD did not create the preceding TOKENIZE state;
after strengthening the fixture to match the consumption path, the two final workspace gates passed. The first complete B4 gate
ran four independent cold builds in a row on this PC at 33/48 jobs. After the first three builds finished between 23:35:48 and 23:39:04,
the fourth started at 23:39:18, and its log stopped at 23:39:34 while compiling `p4-agent-core`; Windows
booted fresh at 23:40:48. There was no CUDA, model LOAD or inference during this interval.

The 23:40:53 Kernel-Power 41 has `BugcheckCode=0`, all bugcheck parameters 0,
`PowerButtonTimestamp=0`, `LongPowerButtonPressDetected=false`, `WHEABootErrorCount=0`. There is no new dump and
no preceding WHEA/GPU/thermal error. The correlation is therefore more direct between sustained cold compiler load and a
hard power loss than with a software crash or model execution. This record alone does not distinguish among PSU,
motherboard protection or thermal as the physical cause.

33/48 affinity limits only the number of concurrent CPUs; it does not limit rustc/LLVM turbo power or the accumulated heat of consecutive builds
to 70%. That assumption is withdrawn. The resource wrapper rejects Build on this PC by default. Only when the user separately
authorizes an emergency run is a maximum of 8 jobs applied, and this is a conservative concurrency cap, not a power measurement.
The B4 baseline and the four mutations were rerun split across Spark, Ubuntu, Mac20 and Mac21, producing the results above.

The first p4-agent run on Mac21 had no Node in the SSH PATH, so after 37 Rust tests passed, only docs-lint failed with an environment error.
Moving the same source and scope to Ubuntu, which has Node, the second round passed all 37 Rust tests and 1 docs-lint.
Product expected values and inputs were not changed.

## Contract review and changes

`OuterEndpoint` has no external client host/port. `ingress_agent` is the ingress agent's network
address, and channel/connection_generation identify that agent's existing OUTER connection.
`Endpoint::agent_address()` and the broker destination already send returns to the ingress agent.
Changing the target to a plain `Agent(A)` would route it into A's agent-control handler, losing the local OUTER delivery information.
The P4E3 wire and the identity of source/target/return_route are kept, and the semantics are stated in the [public contract](../../../docs/event-protocol-v2.md#reception-agent-and-an-outer-reachable-only-through-a-gateway).

The actual defect was that `serve()` registered the `source=Outer(A,...)` of a forwarded request on its own receiving socket even on intermediate B.
Registration is now restricted to the case where the broker's canonical local_address equals source.ingress_agent.
An intermediate agent does not own OUTER's return connection. Payload/model semantics, settlement, native and default limits were not changed.
Source authentication, connection authorization and address alias discovery are not implemented by this check. This is also not a real VPC firewall deployment test.

# 접수 에이전트 경유 엔벨롭 검증

2026-09-15 11:37 KST. 기준 `4f2db5cda`의 FINISH WIP에서 사용자 지시로 접수 경로만 수정했다.
[계획](../../plans/ingress-envelope-20260915.md). **접수 경유·등록 제한 검증은 통과, 전체 workspace는 기존 FINISH 실패로 RED다.**

## 계약 검토·변경

`OuterEndpoint`에는 외부 클라이언트 host/port가 없다. `ingress_agent`는 접수 에이전트의 네트워크
주소이고 channel/connection_generation은 그 에이전트의 기존 OUTER 연결을 식별한다.
`Endpoint::agent_address()`와 broker destination은 이미 반환을 접수 에이전트로 보낸다.
plain `Agent(A)`로 target을 바꾸면 A의 agent-control handler로 들어가므로 로컬 OUTER 배달 정보가 사라진다.
P4E3 wire와 source/target/return_route의 identity를 유지하고 [공개 계약](../../../docs/event-protocol-v2.md#reception-agent-and-an-outer-reachable-only-through-a-gateway)에 의미를 명시했다.

실제 결함은 `serve()`가 전달받은 요청의 `source=Outer(A,...)`를 중간 B에서도 자기 수신 소켓에 등록하는
것이었다. broker의 canonical local_address와 source.ingress_agent가 같은 경우에만 등록하도록 제한했다.
중간 에이전트가 OUTER의 반환 연결을 소유하지 않는다. payload/model 의미·정산·native·기본 한도는 변경하지 않았다.
source 인증·접속 권한·주소 alias 발견은 이 검사로 구현되지 않는다. 실제 VPC 방화벽 배포 시험도 아니다.

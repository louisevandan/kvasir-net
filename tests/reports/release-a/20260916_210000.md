# Release A H0 v8 — I1 실기 전 계약 봉인

상태: 비모델 게이트 GREEN. I0 v8 재실기와 I1-Q64 실기는 아직 미실행이다. 제품 전체 `integrity_baseline=false`.

## 원인과 변경

I0 v7 이후 정적 대조에서 기존 H1/I1 생성기가 LOADED·INFERENCE_WINDOW·DRAINED 관측 장벽을 실행 설정에 넣지 않는 것을 확인했다. 또한 I0 수집기의 원격 artifact 읽기 제한 60초는 64건 장시간 원자료를 보장하지 못한다. [L086](../../../docs/deterministic-execution-register.md)을 새 사전검사와 변이 시험으로 고정하고, 모델 적재 전에 결함을 차단했다.

[H0 v8](../../../test/benchmarks/cluster-inference/release-a/benchmark-spec-qwen122b-h0-v8.json)은 Rust runtime source `b8f5214ba9a88a2bc449889af80aff4b2c3ae8c0`와 기존 3-host 바이너리·모델·분할을 유지한다. 새 I1 실행기·증거 builder·judge와 H1 materializer/I0 collector 변경을 파일 SHA로 결속했다. source bundle은 `925ca6af156ab6a259ee1c7e1b0682626ef0c2a9 HEAD`, 5,329,168 bytes, SHA-256 `7694d1458d33f7259bfbe209470128945cee6af2a53572f7e17f69b86b5bb554`이며 `git bundle verify`를 통과했다. H0 v8 명세 SHA-256은 `9dd17f0a2a0a86f1d56937d0ccf77c54c1d0934c8e1b1298eef2dd61e951d189`이다.

H0 v8은 64건 short32/medium16/long16, 원본 prompt·JSON 오라클·processor·deadline, LOADED·추론 시작·DRAINED 각 15,000 ms, I1 artifact 전송 900초를 LOAD 전 검사한다. 64건 전체 합성 경로는 source/model 출력 출처, 모든 RELEASE, stage·batch·GPU·회수 증거와 short만 유효 모델 token으로 세는 점수표를 검증한다.

## 실행한 비모델 검사

- `python test/benchmarks/cluster-inference/release-a/verify-h0-v8.py`: 21개 고정 검사 통과. H1 materializer 10, I0 runner 7, I1 runner 9, I1 raw builder 5, I1 judge 3, 64건 전체 경로 5, benchmark spec 4개 시험을 포함한다.
- 64건 전체 경로의 누락 요청, 오답, processor 누락, GPU 표본 누락 변이가 각각 거부됐다. spec의 관측 장벽 누락/0과 I1의 짧은 artifact 전송 제한, 사례/오라클 결속 누락도 거부됐다.
- `git bundle verify target/p4-h0-v8-source-925.bundle`: 완료. 이 bundle과 명세는 로컬 ignore된 `target/`에서 보존한다.

## 실기 진입 조건과 다음 행동

이 결과는 실행 사전계약의 증명이며 I1 수용이나 성능 개선이 아니다. 변경된 최종 source에서 I0-S/M/L을 같은 3물리 host로 다시 실행해야 한다. 사전검사에는 새 task agent의 실제 advertised 주소 왕복, 세 host nodes/native child 0, 보호 agent 보존, 네 controller 터널 PID/명령과 17개 결속 해시가 포함된다. I0가 정답·EOS·RELEASE·회수를 모두 다시 통과한 뒤에만 I1-Q64 한 LOAD를 시작한다. I1은 64/64 정상 응답과 원자료/점수표를 같은 추론창에서 판정한다.

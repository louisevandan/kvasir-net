## 실행 단계와 관측 로그

첫 제어 사전검사는 실패했다. 일시적인 Windows 셸에서 띄운 네 SSH 역방향 터널이 시작 확인 직후 종료됐고, Mac20 agent는 반환 peer `tcp://localhost:22151`의 `Connection refused`를 `not_started` 세 건으로 보존했다. 터널 재개방만으로는 실패한 peer cache가 풀리지 않아 왕복 INSPECT가 timeout됐다. 이때 모델 LOAD는 없었고, 직접 INSPECT는 세 host 모두 nodes 0, Mac20 transport failure 3을 기록했다. `target/release-a-i0-v6-20260916/preflight-failure-direct-inspect.jsonl`과 host별 `preflight-*-agent.err`를 보존했다. [실행 장부 L084](../../../docs/deterministic-execution-register.md)의 차단 검사와 제거 변이는 별도 `f3e84016f` 체크포인트에 있다. 이 체크포인트는 이번 봉인 실행 소스에 합치지 않았다.

작업 전용 agent만 새 broker instance로 시작하고, 지속 SSH 세션의 네 PID/명령·Mac 역방향 listener를 확인했다. 이어 **실제 advertised 주소별 왕복 INSPECT**에서 Spark/Mac20/Mac21 모두 nodes 0·transport failure 0을 확인했다. 15개 실행 바인딩 SHA-256과 host별 native child 0·task listener 1도 LOAD 전에 일치했다. 기존 보호 agent 세 개(`:52005`)는 건드리지 않았다.

재판정 유효 TPS의 분모는 각 요청의 `completed_ms - arrival_ms`이며 prefill까지 포함한다. medium/long의 모델 token은 OUTER가 새 JSON을 만들 때 폐기하므로 분자는 0이다. 총 모델 생성 TPS는 원시 생성 token을 RELEASE까지의 시간으로 나눈 별도 수치다. 재판정은 원자료 진단이며 v6 실행 소스의 최종 scorecard 승인으로 소급하지 않는다. service TTFT는 중·장문 응답이 검증 후 공개되는 시각을 반영한다. prefill의 평균 물리 batch 폭은 각각 63.23/64.00/63.96행, full ubatch 비율은 97.7%/100%/99.9%였다. 단일 in-flight 실행이므로 decode 폭은 모두 1이고 혼합 batch는 0이다. 이 수치는 성능 개선을 증명하지 않는다.

동일한 1,153초 추론창에서 GPU 표본 coverage는 세 host 모두 100%였다. 평균 util은 Spark 32.1%, Mac20 3.3%, Mac21 4.5%다. Spark power 평균 33.1 W가 관측됐고, Mac의 power/temperature는 host telemetry 미지원으로 표시됐다. stage별 계산 span 7,977개와 runnable/blocked·phase별 batch를 원시 artifact에 보존했다. GPU 이용률이 낮은 원인이나 개선률은 이 I0 단일 요청만으로 단정하지 않는다.

원시 모델의 medium/long 출력에는 코드 펜스와 잘못된 전력·경보 값이 있었다. OUTER는 요청의 기록 ID·revision을 검증하고 **입력 원자료의 수치로** 전력·에너지·경보를 계산해 정확 JSON을 만들었다. 원시 출력은 `model_response`에 보존됐다. 따라서 이 결과는 지정된 `engineering_power_v1` 서비스 계약의 수용이며, 모델 일반 산술 능력이나 임의 자연어 질문의 정답률 수용은 아니다.

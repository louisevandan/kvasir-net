## Counterexample, fix and real consumption path

The first version of the new `probe-memory-plan.py` did not pass the config's environment to the native child.
In the default local Windows CUDA order, CUDA0 was the RTX4080, and `fits:true` from the same PLAN alone could not catch this misidentification.
The tool was fixed to pass the declared environment and args, and an exact device description check via `--expect-device` was added.
It records the native binary/config/run-check script SHAs and raw stdout/stderr, and rejects missing or duplicate PLANs, timeouts and device mismatches.
`public_plan_acceptance` and `release_acceptance` are always false.

`probe-memory-plan-mutations.py` runs independent source copies with real Python.
The same native SHA `97003fc1077f18b34d7718c105da50e3e89323f99c6052ca11149268cc595aba` was confirmed every time.

| Real native run | Result |
| --- | --- |
| config PCI_BUS_ID / expected 3090 | native exit 0, check exit 0, actual description 3090 |
| same config / wrong expectation 4080 | native exit 0, check exit 1 |
| environment passing removed | actual description changes to 4080 and the expected-3090 check exits 1; removal of the fix detected |
| device check removed / wrong expectation 4080 | check exits 0 and wrongly approves; mutation detected by the baseline rejection counterexample |

The 4 runs and 2 removal mutations PASS. The source copy SHAs were checked against each run record. These are mutations of the Python runner,
not native recompilation mutations, and the native source/binary was not changed. The first wrong-device result is preserved, and the rerun used a separate new path.
The 4 POSIX hosts ran the final Python helper; .17 ran a separate PowerShell preflight that records the same environment passing, native framing,
expected device check and timeout. The .17 script SHA and the full script are also in the raw evidence.

# Release A 무결성 우선 시험 계약·로드맵 재조정

2026-09-16 13:14 KST. 이 단계의 판정은 **시험 계약 GREEN, 제품 무결성 미실행**이다. 구성요소
안전성 완료를 제품 완료로 세던 순서를 폐기하고, Qwen122B I0–I4 무결성을 먼저 통과한 뒤 P0–P3
성능 개선으로 이동하도록 현재 로드맵과 검증 규약을 바꿨다. 이 단계에서는 모델을 LOAD하거나 성능
수치를 새로 측정하지 않았다.

## 현재 제품 판정

- 과거 B5 source의 단일 요청은 정답119 token/EOS였지만 현재 runtime source의 단일 요청 수용은 아니다.
- H1 1차는64건 중8건만 완료했고 H1 2차는 terminal artifact가 없어 INVALID다.
- 따라서 현재 Qwen122B 서비스 무결성은 RED/미수용이며 성능 개선율은 미증명이다.
- 기존 H1 3차 반복은 취소했다. 계약이 다른 I0부터 독립 실행한다.

## 먼저 고정한 시험

[실행 계획](../../plans/release-a-integrity-first-20260916.md)과
[machine-readable 계약](../../../test/benchmarks/cluster-inference/release-a/integrity-test-spec-qwen122b-i0-v1.json)은
다음14개 arm을 고정한다.

- I0: 현행 source의 short/medium/long 단일 요청 3개.
- I1: 같은 load의 closed-loop 정상 corpus64건.
- I2: cold8, sustained8×8, 같은 load recovery3×8.
- I3: overload80, cancel, slow/disconnected edge, middle-stage restart, late old-generation return.
- I4: 같은 load32×8, 최소93분 soak와 정상 NODE_UNLOAD 회수.

모든 arm은 요청별 정상 응답·EOS·deadline·terminal·RELEASE뿐 아니라 TTFT, ITL, prefill/decode rows/s,
useful generation TPS, phase별 batch 폭/채움, runnable/blocked, 동일 분석창의 host별 GPU 표본과 자원
스냅샷, 실제3host shard/KV/stage/전송 증거를 요구한다. 필드 누락은 RED가 아니라 INVALID이며 실행을
다시 성공으로 해석하지 않는다.

## 남은 구현과 다음 행동

현재 계약은 `status=planned`, `integrity_baseline=false`, `performance_improvement_claimed=false`다.
실제 event artifact에서 scorecard와 arm bundle을 만드는 collector/materializer, H0의 파일·judge hash 봉인,
bounded deadline→partial artifact→FINISH→UNLOAD 실행 경로는 아직 I0 실행 전 구현 대상이다.

다음 첫 행동은 현재 source/binary/model/topology와 이 계약·판정기를 새 H0 revision에 결속하고 fresh
checkout에서 고정 gate를 통과시키는 것이다. 그 뒤 원격 task agent 사전검사를 하고 I0-S/M/L을 한 번
실행한다. I0 실패는 현재 제품 무결성 RED로 확정하며 같은 arm을 반복하지 않고 artifact가 증명한 원인에
자동 차단 수단을 추가한다.

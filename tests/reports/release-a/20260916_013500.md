## Causes of repeated failures and mandatory reuse

`first_pass=fail`. In the first complete regression run, 8 HF integration tests failed in a remote environment without a `python`
alias. With no product defect and no expected-value change, setting `HF_TEST_PYTHON=/usr/bin/python3` explicitly let the final gate
pass.

On the initial Mac direct return route, SSH and `nc` succeeded, but outbound connections from agent processes started over SSH
got `No route to host (65)`. A plain proxy was rejected because the broker requires `route.ingress_agent == local_address`.
This was solved by matching each agent's advertised address to the actual return route and then running a bidirectional INSPECT round trip
to all three agents over the same OUTER connection.

In the first normal Qwen122B run, native ports `53250–53252` overlapped the macOS dynamic range `49152–65535`, and
Mac21 readiness ended with EINVAL. The second run's `43250–43252` was outside the macOS range but inside the Linux range
`32768–60999`. After the Spark listener bind failed, native main joined the stdin watcher thread and
hung with no error output. The actual thread states matched: main `futex_do_wait`, stdin `anon_pipe_read`, listener 0.
A normal UNLOAD succeeded on the two Mac nodes, and on Spark the task agent's exit closed stdin, which reclaimed native as well.
After that, nodes/native/listener 0 were re-confirmed on all three hosts.

This failure was not left as prose only. `tools/validate_event_runtime_preflight.py` checks the sealed config and the immediately preceding
evidence for an exact advertised-address round trip, the OUTER return address, the per-OS dynamic port range, and nodes/transport
failure/task native/listener 0. The second configuration is rejected automatically, and only the `23250–23252` configuration was approved.
Four cases were pinned as tests: normal, contaminated return route, dynamic-port collision, and a leftover node/native counterexample. The same rules
went into `AGENTS.md` and roadmap §0, making them prerequisites for later remote real-hardware runs.

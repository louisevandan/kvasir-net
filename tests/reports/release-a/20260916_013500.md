## 경계 판정과 기록된 기대값 오류

세 번째 경계 실행은 adapter error content, 코드 `LLAMA_ADAPTER_EVENT_REJECTED`, exact ±1 detail,
실패 이유가 든 failed state, input/completion/native response/pending 0을 모두 기록했다. 실행 하네스는
오래된 기대값인 공통 P4 error와 `empty` state를 요구해 exit 1이었으나, 보존 artifact를 대상으로 한
독립 판정의 8개 안전성 조건은 모두 참이다. 기대값을 완화하거나 네 번째 모델 실행을 하지 않았다.
LOAD 실패를 관측 가능한 failed state로 보존하는 현재 계약을 기준으로 판정했다.

## 반복 실패의 원인과 강제 재사용

`first_pass=fail`이다. 회귀 첫 완전 실행은 `python` 별칭이 없는 원격 환경에서 HF 연동 시험 8개가
실패했다. 제품 결함이나 기대값 변경 없이 `HF_TEST_PYTHON=/usr/bin/python3`를 명시해 최종 gate를
통과했다.

초기 Mac 직접 반환 경로는 SSH·`nc`가 성공해도 SSH로 시작한 agent 프로세스의 outbound 연결이
`No route to host (65)`였다. 단순 proxy는 broker가 `route.ingress_agent == local_address`를 요구해
거부했다. 각 agent가 광고한 주소를 실제 반환 경로와 일치시킨 뒤 세 agent를 대상으로 같은 OUTER
연결에서 양방향 INSPECT 왕복을 수행해 해결했다.

정상 Qwen122B 첫 실행의 native port `53250–53252`는 macOS dynamic 범위 `49152–65535`와 겹쳐
Mac21 readiness가 EINVAL로 끝났다. 두 번째의 `43250–43252`는 macOS 범위 밖이지만 Linux 범위
`32768–60999` 안이었다. Spark listener bind가 실패한 뒤 native main은 stdin 감시 thread를 join해
오류 출력 없이 멈췄다. 실제 thread 상태가 main `futex_do_wait`, stdin `anon_pipe_read`, listener 0과
일치했다. 정상 UNLOAD는 Mac 두 node에서 성공했고 Spark는 task agent 종료가 stdin을 닫아 native까지
회수했다. 그 뒤 세 host nodes/native/listener 0을 다시 확인했다.

이 실패를 문장으로만 남기지 않았다. `tools/validate_event_runtime_preflight.py`가 봉인 config와 직전
증거의 정확한 advertised-address 왕복, OUTER 반환 주소, OS별 dynamic port 범위, nodes/transport
failure/task native/listener 0을 검사한다. 두 번째 설정은 자동 거부되고 `23250–23252` 설정만 승인됐다.
정상, 반환 경로 오염, dynamic-port 충돌, 잔존 node/native 반례 4개를 시험으로 고정했다. 같은 규칙을
`AGENTS.md`와 로드맵 §0에 넣어 이후 원격 실기의 선행 조건으로 만들었다.

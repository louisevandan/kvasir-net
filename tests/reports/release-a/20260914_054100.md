## 준비 실패와 수정

Windows의 이전 진단 빌드는 `CMAKE_CXX_FLAGS=/utf-8`가 기본 `/EHsc`를 덮었다. 이를 최종 배포 후보로
승격하지 않고 `/EHsc /utf-8`를 명시했다. CPU는 새 `native-cost-cpu-final`에 재빌드했다.
CUDA 초기 결과는 실모델 실행 전에 `cuda-preliminary-binaries`에 보존하고, flags와 최종 patch identity로
재구성/재빌드했다. 현재 CUDA 실모델 증거는 수정 뒤 바이너리다. 이전 CPU 보고의 바이너리/로그는 보존했다.

첫 POSIX archive는 Windows 패치 적용 시 CRLF가 남아 네 host 모두 **컴파일 전 patch seal 검사에서 거부**됐다.
별도 LF archive를 만들어 같은 native diff SHA를 확인한 뒤 새 `*-cost-lf` 경로에서 빌드했다.
첫 archive와 실패 launcher 로그를 보존했다. source hash oracle을 완화하지 않았다.
Ubuntu Git은 시스템 설치 대신 `$HOME/p4-release-a-tools`에 배포판 Git deb를 추출해 사용했다.
원격 기존 agent/native 프로세스를 종료하거나 기존 배포 폴더를 변경하지 않았다.

## Pre-deployment rejection implementation

`validateNativeDeployment` is now exported from `tools/model-loading/index.ts`. This function rejects the following before
LOAD, and returns post-LOAD conformance only when every `MEMORY_ACTUAL` is present for the same input.

- Discontinuous/unapproved cut, fewer than the minimum physical hosts, native layer device mismatch
- Per-stage upstream/patch mismatch, missing backend/device identity
- required not equal to the weight/context/compute sum, exceeding native free
- Exceeding available minus reserve for a unified pool's device+host, or after summing multiple stages
- Mismatch between the PLAN and the actual allocation/topology/execution shape

Before building the LOAD input, re-checking native C++ `same_stage_memory_allocation` against the real-hardware records
revealed an error: the remaining free and `fits_current_free` in the post-allocation `MEMORY_ACTUAL` were being rechecked with
the PLAN admission rule. The fix makes ACTUAL compare topology/shape/placement/model/context/compute allocation and exclude
the post-allocation observations free/fit from the comparison. A counterexample with ACTUAL free below required and fit=false
was added, and 38/38 plus 4 independent mutations passed on the first run. The post-correction mutation result SHA256 is
`6b08bb2296ee7625a7662f2ea882f49418786330a911cc2b247f3f763741c7f3`.

The 550B fixed values in the existing Release A manifest (10-shard/7-host/8-stage/108 layers) were also replaced with the new
target's 3-shard / minimum 2-host / 48-layer contract. The request SLO, resident and byte boundaries themselves were not relaxed.

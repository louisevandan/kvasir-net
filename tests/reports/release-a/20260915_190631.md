## 배포 전 거부 구현

`tools/model-loading/index.ts`에 `validateNativeDeployment`를 공개했다. 이 함수는 다음을 LOAD 전에
거부하고, 같은 입력에 모든 `MEMORY_ACTUAL`이 있어야 post-LOAD conformance를 반환한다.

- 불연속/미승인 cut, 최소 물리 host 미달, native layer device 불일치
- stage별 upstream/patch 불일치, backend/device identity 누락
- required와 weight/context/compute 합 불일치, native free 초과
- 통합 pool의 device+host 또는 여러 stage 합산 후 available-reserve 초과
- PLAN과 실제 allocation/topology/execution shape 불일치

LOAD 입력을 만들기 전 native C++의 `same_stage_memory_allocation`과 실기 기록을 다시 대조해,
할당 뒤 `MEMORY_ACTUAL`의 남은 free와 `fits_current_free`를 PLAN admission 규칙으로 재검사하던 오류를
발견했다. ACTUAL은 topology/shape/placement/model/context/compute allocation을 비교하고 할당 뒤 관측치인
free/fit은 비교에서 제외하도록 수정했다. ACTUAL free가 required보다 작고 fit=false인 반례를 추가했으며
38/38과 독립 변이4종을 첫 실행에 통과했다. 교정 후 변이 결과 SHA256은
`6b08bb2296ee7625a7662f2ea882f49418786330a911cc2b247f3f763741c7f3`다.

기존 Release A manifest의 550B 고정값 10-shard/7-host/8-stage/108층도 새 target의
3-shard/최소2-host/48층 계약으로 교체했다. 요청 SLO·resident·byte 경계 자체는 완화하지 않았다.

## M42 설치 앱 경로와 정리

M42 `.29`의 설치 앱 경로와 SSH를 같은 것으로 취급하지 않았다. 사용자 profile에는
`S:` → `\\192.168.0.13\file-station` 매핑이 남아 있지만 현재 로그인 사용자가 없고 mapping status가
끊김이라 interactive 예약 작업이 `0x41303`에서 시작되지 않았다. 모델/PLAN/native 프로세스는 생성되지
않았다. 범위가 정해진 예약 작업을 삭제했고 해당 port의 native process0을 확인했다. 이는 P4나 설치 앱의
기능 실패 판정이 아니라 현재 사용자 세션 부재다.

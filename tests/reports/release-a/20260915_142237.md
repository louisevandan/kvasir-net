## Advance decisions

Callers and real consumption paths were cross-checked before the run. The agent detaches only the live route of the socket that received u32-LE 0,
drains the output queue it already owns, and then sends the 0 ACK. The replacement route, failure tombstone, receipt and KV
are not changed. When the Rust/HF clients receive a valid abnormal length, they keep the whole first frame in the
client buffer within the same deadline and record the frame/buffer byte counts in the error. EOF/timeout preserves the partial bytes, and
an oversized length does not allocate a body. Sends and retries after FINISH are not allowed.

## Implementation

- `tools/event-drive/src/run/wire.rs`: the path that failed after looking at only 4 bytes now receives the first valid frame completely.
  The preserved byte counts for EOF/timeout/oversized length are included in the error and recorded in the existing run `cleanup_error`.
- HF `integration/transport`: added `finish_unexpected_output` with the same receive-preservation rule; it is cleared on a normal
  ACK. A socket timeout propagates the original error, but the received bytes remain in this diagnostic buffer.
- Added Rust EOF/timeout/oversized-length counterexamples and HF tests for split ACK, 721byte, partial EOF/timeout and oversized length.
  The agent route/queue/cost code was not changed.

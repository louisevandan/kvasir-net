[연결 회수 계획](../../plans/release-a-transport-20260915.md)을 첫 완전 gate 성공률 중심으로 재개했다.
초기 [3회 실패 기록](20260915_044735.md)은 보존한다. 이번 결과는 FINISH의 로컬 수용이며
Qwen122B 다중 컴퓨터 Release A 완료가 아니다.

## 사전 결정

호출자와 실제 소비 경로를 실행 전에 대조했다. agent는 u32-LE 0을 받은 socket의 live route만 분리하고,
이미 소유한 출력 queue를 drain한 뒤 0 ACK를 보낸다. replacement route, failure tombstone, receipt와 KV는
바꾸지 않는다. Rust/HF client는 유효한 비정상 길이를 받으면 같은 deadline 안에서 첫 frame 전체를
client buffer에 보존하고 오류의 frame/buffer byte 수를 남긴다. EOF/timeout은 부분 bytes를 보존하며,
과대 길이는 body를 할당하지 않는다. FINISH 뒤 send와 재시도는 허용하지 않는다.

## 구현

- `tools/event-drive/src/run/wire.rs`: 4byte만 보고 실패하던 경로를 첫 유효 frame 완전 수신으로 변경했다.
  EOF/timeout/과대 길이의 보존 byte 수를 오류에 포함해 기존 run `cleanup_error`에 남긴다.
- HF `integration/transport`: 같은 수신 보존 규칙의 `finish_unexpected_output`을 추가하고 정상 ACK에서는
  비운다. socket timeout은 원래 오류를 전달하되 수신 bytes는 이 진단 buffer에 남는다.
- Rust EOF/timeout/과대 길이 반례와 HF split ACK·721byte·부분 EOF/timeout·과대 길이 시험을 추가했다.
  agent route/queue/비용 코드는 변경하지 않았다.

## Changed proof boundaries

1. `P4_EVENT_GATE_INFERENCE_WINDOW` records the absolute inference start time and then holds the peak observation right for 15 seconds.
2. `P4_EVENT_GATE_DRAINED` holds the drain observation right for 15 seconds after every terminal, RELEASE and telemetry completes, before NODE_UNLOAD.
3. The runner collects the INSPECT node count and task-owned native/listener state only at the barriers: before LOAD, at peak, after drain and after UNLOAD.
4. Agent INSPECT provides cumulative hop data write counts and byte counts. I0 cross-host bytes are the actual increase between peak and drain.
5. GPU samples are collected at 1-second intervals from Spark's `nvidia-smi` and the Macs' `ioreg PerformanceStatistics`, and bound to the runtime's absolute time window.
6. At shutdown, only the task agent, proxy and tunnel whose PID and full command were sealed are stopped, and the protected agent is checked again.

## Failures and automatic blocks

- The first remote compile failed because two test callers omitted the new counter argument of `write_hop_loop`. Both callers were fixed, and an assertion on the actual counter increment was added.
- In the next remote test run, all 145 product tests passed, but the docs gate could not find Node on PATH, so the run as a whole was RED. Without any source change, a confirmation run with the installed Node path pinned in the runner passed all 146.
- The mistake of starting Rust verification locally was stopped immediately. Since then, the build/test runner requires a remote bundle, an exact commit, a job count at no more than 70% of CPUs, and a `nice -n 10` check.
- A pre-run failure caused by mistaking an old bundle origin on the remote for the latest ref was pinned as L076. Patch-based deployment was then retired, and only verified commit bundles are used.

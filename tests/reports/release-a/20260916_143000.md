## 바뀐 증명 경계

1. `P4_EVENT_GATE_INFERENCE_WINDOW`는 절대 추론 시작 시각을 기록한 뒤 15초 동안 peak 관측권을 가진다.
2. `P4_EVENT_GATE_DRAINED`는 모든 terminal·RELEASE·telemetry 완료 뒤, NODE_UNLOAD 전에 15초 동안 drain 관측권을 가진다.
3. runner는 LOAD 전, peak, drain 뒤, UNLOAD 뒤의 INSPECT node 수와 task-owned native/listener 상태를 장벽에서만 수집한다.
4. agent INSPECT는 누적 hop data write 수와 byte 수를 제공한다. I0의 교차 host byte는 peak와 drain 사이의 실제 증가량이다.
5. GPU 표본은 Spark의 `nvidia-smi`와 Mac의 `ioreg PerformanceStatistics`에서 1초 간격으로 수집하고 runtime 절대 시간창에 결속한다.
6. 종료 시 PID와 전체 command가 봉인된 task agent·proxy·tunnel만 정지하고 protected agent는 다시 확인한다.

## 실패와 자동 차단

- 첫 원격 컴파일은 `write_hop_loop`의 새 counter 인수를 두 시험 호출자가 빠뜨려 compile failure였다. 두 호출자를 수정하고 실제 counter 증가 단언을 추가했다.
- 다음 원격 시험의 제품 시험 145개는 통과했지만 docs gate가 PATH의 Node를 찾지 못해 전체는 RED였다. 소스는 바꾸지 않고 설치된 Node 경로를 runner에 고정한 확인 실행에서 146개가 모두 통과했다.
- 로컬에서 Rust 검증을 시작한 실수는 즉시 중단했다. 이후 build/test runner에는 원격 bundle, 정확한 commit, CPU 70% 이하 jobs, `nice -n 10` 검사를 필수화했다.
- 원격의 과거 bundle origin을 최신 ref로 오인한 실행 전 실패는 L076으로 고정했다. 이후 patch 배포를 폐지하고 검증한 commit bundle만 사용했다.

기존 task agent와 proxy/tunnel은 nodes 0 상태에서 정확한 PID·command를 확인한 뒤 회수한다. H0 v5 binary로 새 task 환경을 만들고 advertised route 왕복과 pre-LOAD nodes/native 0을 통과시킨 다음, 봉인된 generation으로 I0-S/M/L을 한 LOAD에서 한 번 실행한다.

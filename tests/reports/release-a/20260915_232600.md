# Release A A-BYTES B2 native 실행 전 completion 예약

2026-09-15 23:26 KST. 구현 기준 P4 소스는
`c16cbfa2abe8e7bc0bd7ce4f3e4c568f6a6c0569`다. 판정은 **B2 GREEN, A-BYTES 전체와
실제 inference 미수용**이다. 다음 gate는 B3 수명별 INSPECT 분리와 source/hop receipt 보유 검증이다.

## 구현과 소유 경계

backend 중립 completion mailbox에 `CompletionReservationGroup`을 추가했다. group은 first/middle
native 호출 전에 forward 한 개와 observation fan-out 전체의 count/retained bytes를 합계로 한 번
예약한다. 각 Event는 실제 비용 이하의 claim으로 분리되고, 분리 전후 전체 사용량은 변하지 않는다.
publication은 이 claim을 같은 mailbox에 이동한다. 예약 실패나 개별 Event의 상한 초과는 원본 group을
유지하며 scheduler, flight, KV, native 호출, event ID, effect, 출력에 아무 변화도 만들지 않는다.

llama.cpp worker의 first/middle physical 경로와 서비스 관측·stage span·feedback을 모두 같은 예약에
연결했다. 공통 core에는 llama.cpp tensor, stage, model shape 타입을 넣지 않았다. 실제 저장소 비용은
`Event`의 소유 allocation capacity를 기준으로 계산하며 payload 길이나 queue 행 수로 대체하지 않는다.

llama.cpp/HF 실제 모델 회귀는 B5에 남아 있다.

## 실패와 원인

`first_pass=fail`이다. 첫 package 회귀에서 기존 owned ring fixture가 completion store 4 MiB와 LOAD를
우회해 주입한 completion profile 512 MiB를 함께 사용해 새 일관성 검사를 실패했다. 제품 경로를 완화하지
않고 fixture의 store/profile을 같은 64 MiB로 맞췄다. 물리 result 상한 33 MiB와 요청 수 16은 그대로다.
정확한 ring 반례와 package 전체를 다시 실행해 통과했고 최종 workspace 두 gate가 동일하게 통과했다.

첫 변이 초안은 예약 자체를 제거해 native 이후 full publication에서 의도적으로 정지했다. 원인 지점을
확정한 뒤 reserve를 native 뒤로만 이동하는 유한 변이로 바꾸어 동일 반례가 즉시 실패하는 것을 확인했다.
이 초기 정지는 정상 결과나 최종 변이 증거로 세지 않았다.

## Notable findings (fed back into design/config)

1. **Docker Desktop/WSL2 ignores `deploy.device_ids`** — all GPUs are exposed regardless.
   Fix: pin at CUDA level via `CUDA_VISIBLE_DEVICES=GPU-<uuid>` per node. Verified working (T1).
2. **llama.cpp build gating**: `llama-cli`/`llama-completion` require `LLAMA_BUILD_COMMON`
   AND `LLAMA_BUILD_SERVER` (cli lives behind the server gate). Set in root CMakeLists.
3. **`llama-cli` is interactive-only now** ("`-no-cnv` not supported, use llama-completion").
   One-shot scripted runs must use **`llama-completion`**.
4. **Git-Bash MSYS path mangling** turns `0.0.0.0` into a Windows path when calling
   `docker exec`. Fix: `export MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL='*'` (added to scripts).
5. **Heterogeneous-FP divergence**: 4080 (sm_89) vs 3090 (sm_86) split compute is not
   bit-identical to single-GPU. Greedy decoding can flip near-tie tokens. Expected; the
   equivalence bar is semantic + reproducible, not bitwise.

## Conclusion

Distributed inference across two physical GPUs in two containers is working via the stock
llama.cpp RPC backend (layer-split pipeline, hidden-state boundary transfer, KV owned by the
layer-owning device). Harness (docker/GPU/network) validated. Ready for M2: per-node local
partial loading (linkcpp's contribution) to remove master weight upload.
